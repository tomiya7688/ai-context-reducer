# AIに作業を頼むためのひな型

AIに毎回同じ情報を伝えずに済むよう、用途の違うひな型を用意しています。繰り返し困っていることに合うものだけ使い、例をプロジェクトの事実や資料へのリンクに置き換えてください。

| ひな型 | 何をするか | 使う場面 |
| --- | --- | --- |
| [AIへの作業ルール（AGENTS.md）](AGENTS.md) | AIが作業で守る決まりと、詳しい説明の場所を伝えます。 | 同じルールを何度も伝えたり、AIに作業方法を探し直させたりしている。 |
| [プロジェクトの基本情報（PROJECT_CONTEXT.md）](PROJECT_CONTEXT.md) | プロジェクトの目的、機能、制限、確認方法をまとめます。 | AIに過去の作業や複数の資料から、同じ事実を何度も探させている。 |
| [今回の作業メモ（CONTEXT_PACK.md）](CONTEXT_PACK.md) | 今回の目的、条件、資料、確認方法をまとめます。 | 一つの作業が複数の会話にまたがる、または引き継ぎが必要。 |

作業ルールを書くファイル名の一例が `AGENTS.md` です。プロジェクトの事実や今回だけの条件とは別にしておくと、必要な情報だけAIに渡せます。ひな型を置いても、AIが自動で読むとは限りません。読み方の確認や依頼文での指定方法は[作業場所に合った指示書を読ませる](../docs/jp/手法/AIに作業場所に合った指示書を読ませる.md)を参照してください。すべてのひな型を作る必要はありません。

## ひな型をどこへ置き、AIにどう読ませるか

必要なひな型だけをプロジェクトへコピーします。共通の作業ルールはリポジトリ直下の `AGENTS.md`、プロジェクトの機能や制限は同じ場所の `PROJECT_CONTEXT.md` に置きます。今回の作業メモは、複数日にまたがる場合に限り `CONTEXT_PACK.md` として置き、作業後に片づけます。

詳しい手順や一覧を `docs/` に作った場合は、そのファイルを読む条件と相対パスを `AGENTS.md` に書きます。たとえば「保存形式を変更するときは `docs/data-format.md` を読む」と記します。使うAIが `AGENTS.md` を自動で読むか確認し、自動で読まない場合は依頼文にファイルのパスを書いてください。文書を置いただけで、AIがその内容を知るわけではありません。

```text
project/
  AGENTS.md                 # 作業の入口。下の資料をいつ読むか書く
  PROJECT_CONTEXT.md        # 何度も使うプロジェクト情報
  docs/
    data-format.md          # 詳しい仕様。必要な作業だけで読む
  CONTEXT_PACK.md           # 複数日にまたがる今回の作業だけで使う
```
