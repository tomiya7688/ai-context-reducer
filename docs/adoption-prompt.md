# 導入プロンプト

この文書は、`ai-context-reducer` の方針を別プロジェクトへ短いコンテキストで導入するためのプロンプト例です。

## 最短版

```text
このプロジェクトに ai-context-reducer の方針を導入してください。

まず README と AI_CONTEXT.md 相当の索引を確認し、必要なら templates/AI_CONTEXT.md を参考に作成してください。
リポジトリ全体を無条件に読まず、差分・索引・現在の作業対象を優先してください。
詳細設計は必要時のみ原典を確認し、要約を原典の代替にしないでください。

導入のための変更は最小限にし、既存構造を壊さないでください。
```

## URLを渡す場合

```text
次の方針をこのプロジェクトへ導入してください。
https://github.com/tomiya7688/ai-context-reducer

導入時は、この方針リポジトリ自体を大量に読み込まないでください。
まず README、templates/AI_CONTEXT.md、必要な説明だけを読み、対象プロジェクト用の AI_CONTEXT.md を最小構成で作成してください。

その後は、全体読み込みではなく差分中心・必要情報の段階取得を基本にしてください。
```

## 導入時の期待動作

AI は原則として次の順に進めます。

1. 対象プロジェクトの README・主要構成・既存のAI向け指示を確認する。
2. `AI_CONTEXT.md` がなければ作成し、あれば必要最小限の改善だけ行う。
3. 読むべき資料、必要時だけ読む場所、通常無視する場所を整理する。
4. 現在の作業対象が明確なら `Current Work` に短く反映する。
5. 既存の設計資料や規約を `AI_CONTEXT.md` へコピーせず、参照先として記載する。
6. 以後の作業では Git 差分と直接依存を優先する。

## やらないこと

- 導入のために対象リポジトリ全体を精読する
- `AI_CONTEXT.md` に設計書全文をコピーする
- AI専用ファイルを大量に追加する
- 既存の文書構造を無理に作り直す
- コンテキスト削減のためだけに複雑な仕組みを導入する

## 目標

導入自体のコンテキスト消費を小さく保ち、短い会話や短期間のセッションでも適用できることを目標とします。

この方針は特定のAI製品に依存せず、Claude、ChatGPT、Codex、その他のAI開発支援環境でも同じ考え方で利用できることを想定します。
