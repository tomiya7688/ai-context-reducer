## 利用者向け文書の書き方

利用者向け文書は、初めて読む人が作業内容をすぐ想像できるようにします。

- 最初に、どんな人がどんな場面で使う説明かを書く。
- 例の前に、例のプロジェクトや困りごとを説明する。架空の例ならそう明記する。
- 誰が何をするかを明記する。読む人が選ぶ・用意する・確認する行動は「人が」「依頼する人が」と書き、AIに任せる行動は「AIに〜させる」「AIに〜を頼む」と書く。AIに直接渡す例文の中では、AIが実行する指示として書く。
- 結論や推奨手順を先に書き、その理由を後に続ける。
- 専門用語は必要なものだけ使い、初めて出る場所で意味を説明する。手法の名前は、内容を説明した後に付ける。
- 方法を紹介する利用者向け文書には、使う場面、選ぶ基準と例、AIへの具体的な指示例、読む量が減る理由を書く。
- 手法を説明する文書は、使う場面や手順の後にAIへの指示例を置き、その後に読む量が減る理由を説明する。補助ツールがある場合は、説明の末尾に箇条書きで紹介し、何をしてくれるかと限界を書く。用語は別の節にし、必要なら最後に手法の名前を書く。
- 手法の根拠に外部の研究論文を使った場合は、根拠となる説明の近くに出典を示し、文書の末尾に「参考文献」を設けて、論文名・著者・発表年・掲載先・リンクを記載する。論文以外の外部ページは、この参考文献欄には含めない。
- 目次、導入手順、プロジェクト全体の概要など、手法を説明しない文書に同じ節を無理に追加しない。文書の目的に合う構成を使う。
- 読者向けの手法説明と、このリポジトリ固有の設計・編集・配布・リリース手順を同じ場所に混ぜない。
- 一つの段落で一つのことを説明し、同じ結論を別の言葉で繰り返さない。
