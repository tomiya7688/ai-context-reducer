# 現在の状態を短くまとめる

プロジェクトで今できること、分かっている制約、まだできないことを、短い文書にまとめておきます。作業のたびにREADMEや過去のIssueを読み直さなくても、現時点の前提をつかめるようにするためです。詳しい仕様や今回の作業内容を、この要約に書き写すものではありません。

## 例：CSV読込機能の現状

たとえば、次のような要約を置きます。

> CSV読込はUTF-8に対応。日付はタイムゾーンを扱わない。Excel形式の読込は未対応。詳しい日付形式は `docs/csv-format.md` を参照。

「Excel形式にも対応したい」という依頼を受けたAIは、この要約から現在の対応範囲を知り、CSV形式や日付の過去の議論を最初から読み直さずに、該当機能と今回の要件を確認できます。要約は調査の入口なので、具体的な実装や細かな日付仕様を変更するときは、リンク先の説明、コード、テストを確認します。

## 何を書くか

繰り返し作業で前提になる事実に絞ります。

- 現在利用できる主な機能
- 現在の制約
- 既知の未対応事項
- 詳細を確認するための参照先

すべての機能や未完了Issueを並べる必要はありません。作業の判断に使わない情報を増やすと、要約自体が毎回読む負担になります。

## 更新するときの注意

実装やテストと食い違う記述は、現在の事実として扱わず確認します。機能を変更したら、今回の変更に関係する要約の記述と参照先を更新します。未確認の内容は、確定した事実のように書かず、未確認だと分かる形にします。

この要約は、詳細仕様、変更履歴、優先順位、作業ごとの完了条件の代わりにはなりません。それらが必要な作業では、それぞれの原文書やIssueを確認します。
