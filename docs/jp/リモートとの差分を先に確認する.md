# リモートとの差分を先に確認する

複数の人やAIが同じリポジトリを更新する場合、手元のコピーを用意した後で、共有先のコードが変わっていることがあります。作業を始めるときに前回からの変更箇所だけを確認すれば、変わっていないファイルをすべて読み直さずに、今の作業へ影響する更新を見つけられます。

## 例: 共有リポジトリで別の人が変更していた

CSVの読み込み処理を直そうとしている間に、別の人が日付変換やそのテストを更新したとします。作業前に共有先との差分を確認すると、変更されたファイル名と概要から日付変換が関係すると分かります。その実装とテストの変更を先に読み、今回の修正への影響を判断できます。変わっていない画面や別機能のコードを読み直す必要はありません。

```text
前回確認した状態と共有先を比べる
  -> 変更されたファイルと概要を見る
  -> 今回の作業に関係する差分を読む
  -> 判断できない場合は関連する元ファイルへ広げる
```

## 最初に見る情報

共有先から新しい変更を取得した後、まず変更の概要を確認します。概要には、更新の短い説明、変更されたファイル、変更量、必要に応じて短い差分抜粋を含められます。差分とは、変更前後で追加・削除された行の表示です。

概要で変更の影響が分かれば、関係する差分と直接の依存先だけを読みます。変更の意図や結果が不明なときは、対象ファイル全体、設計資料、テストへ調査を広げます。短い概要だけで判断を確定しません。

差分抜粋を短くする場合は、省略した範囲があることを明記し、必要なときに元の差分を確認できるようにします。短い表示は変更箇所を見つける入口であり、完全なレビューの代わりではありません。

## 確認と取り込みを分ける

共有先の変更を確認することと、その変更を手元のコピーへ取り込むことは別です。差分を見るだけなら、作業中の変更を上書きしない方法で確認します。自動で更新する仕組みを使う場合も、手元に未保存の変更や共有先と食い違う変更があるときは止め、判断を人へ戻します。

## 使う場面と使わない場面

複数の人やAIが共有リポジトリを更新し、前回の確認後に変更が入る場合に役立ちます。一人で短時間作業し、共有先が変わっていないと分かっている場合は、差分の仕組みを追加しなくて構いません。対象の差分から影響が分からない場合は、必要な関連ファイルや検証範囲まで確認します。
