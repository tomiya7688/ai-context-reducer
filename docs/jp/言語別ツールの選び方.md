# 言語に合った解析方法を選ぶ

コードを調べる道具は、対象の言語と開発環境によって分かることが違います。まず既に使える道具でファイルや関数の位置を絞り、必要になった場合だけ、依存関係やビルドまで分かる詳しい検査へ進みます。最初からすべてのファイルや開発用ソフトを読み込ませないことで、関係するコードに早くたどり着けます。

## 例：大きなアプリでCSV取込を変更する

PythonとGoで作られたアプリで、CSV取込の不具合を調べるとします。まず軽い解析で、CSVの処理があるファイルや関数、その周辺の名前を探します。該当箇所とテストが見つかれば、他の機能のコードを全部読む必要はありません。

変更が複数の機能に影響しそうなら、ファイル間の参照やパッケージのつながりを追加で調べます。さらに、実際にビルドできるか、型や依存関係に問題がないかまで判断する必要がある場合は、そのプロジェクトで使っているコンパイラーや開発キットを使います。軽い解析だけで分からないことを、分かったふりはしません。

## 解析の深さを選ぶ

ファイル名や関数の位置を探す軽い解析は、言語の実行環境がなくても使える場合があります。ただし、これは読む場所を探すための目安です。プログラムを実行した結果や、型・ビルドの正しさを保証するものではありません。

より詳しい解析では、ファイル間の参照やプロジェクトの設定を調べます。実際のビルド条件や実行時の動作を確かめるには、言語のコンパイラー、開発キット、実行環境が必要な場合があります。たとえばPythonを動かす環境や、C#をビルドする .NET SDK がそれに当たります。何が必要かは解析の内容によって異なります。

## 既存の環境を使う

まずプロジェクトが使っている言語と、現在の環境にある開発用ソフトを確認します。追加の環境がない場合は、使える範囲の解析や通常の検索に戻り、実施できなかった確認を明記します。この調査のためだけに、実行環境や開発キットを自動でインストールしません。

解析結果も、必要な範囲だけを確認します。該当箇所が見つかったら、関連する実装やテストを読みます。小さなプロジェクトで対象とテストがすぐ分かるなら、専用の解析手順を追加する必要はありません。重い解析や広い索引は、大規模なプロジェクトで影響範囲を調べる必要があるときに限って使います。

このrepositoryでの具体的なコマンド、出力場所、各解析段階の仕様は、[`language-setup`](../../tools/common/small/language-setup/README.md)、[`language-run`](../../tools/common/small/language-run/README.md)、[`acr-toolbox`](../../tools/common/native/acr-toolbox/README.md)の説明を参照してください。
