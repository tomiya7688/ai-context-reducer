# LLMが文章を生成するまで

LLMの回答は、完成した文章を内部で一度に作ってから表示しているわけではありません。自己回帰型のLLMは、現在までのトークン列から次のトークンを一つ選び、そのトークンを追加した列からさらに次を選ぶ処理を繰り返します。

この文書では、利用者が文章を入力してから、モデルが続きを生成するまでを処理順に追います。

## 1. システムがモデルへ渡す入力を組み立てる

チャットサービスでは、画面に入力したメッセージだけがモデルへ渡るとは限りません。システム指示、過去の会話、取得した資料、ツールの結果などをサービス側が一定の形式で並べ、モデルへ渡す一つの入力列を作る場合があります。

どの情報をどの形式で含めるかはサービスごとに異なります。モデルは、最終的に渡されたトークン列を条件として次の出力を計算します。

## 2. トークナイザーが文字列をトークンIDへ変える

入力文字列は、[トークン](./トークンとは何か.md)へ分割されます。トークナイザーは各トークンを語彙表のIDへ変換します。

```text
文字列
  ↓
トークン列
  ↓
トークンID列
```

モデルは、このID列をそのまま意味のある数値として扱うのではなく、次の段階で各IDをベクトルへ変換します。

## 3. トークンIDをベクトル表現へ変える

モデルは、各トークンIDに対応する**埋め込みベクトル**を取り出します。埋め込みベクトルは、そのトークンを後続の計算へ渡すための数値列です。

Transformerはトークンの順番も必要とするため、モデルは位置を表す情報も利用します。位置情報の実装はモデルによって異なり、元のTransformerの位置エンコーディング、学習された位置表現、回転位置埋め込みなど複数の方式があります。

## 4. Transformerが各位置の表現を更新する

Transformerブロックは、Self-AttentionとFeed Forward Networkなどを使い、各トークン位置のベクトルを何層も更新します。

Self-Attentionでは、ある位置が参照できる他の位置との関係を計算し、関係の強さに応じて情報を組み合わせます。自己回帰型の生成モデルでは、未来の位置を参照しないように因果マスクを使うのが一般的です。

詳しい内部処理は[Transformerの中では何が起きているのか](./Transformerの中では何が起きているのか.md)と[Attentionとは何か](./Attentionとは何か.md)で説明します。

## 5. 最後の表現から次トークンのスコアを出す

Transformerの最終層から得た表現は、語彙中の各候補トークンに対応する**logit（ロジット）**へ変換されます。logitは、候補同士を比べるための生のスコアです。

生成処理は、logitから候補の確率分布を作るためにSoftmaxを使うことがあります。Softmaxは複数のスコアを、合計が1になる非負の値へ変換する関数です。

```text
最終表現
  ↓
語彙中の各トークンのlogit
  ↓
確率分布
```

## 6. 生成方法が次のトークンを選ぶ

次のトークンを必ず最高確率の候補にする生成方法もあれば、確率分布から候補をサンプリングする生成方法もあります。temperatureやtop-pなどの設定は、候補の選ばれ方を変えます。

そのため、同じ入力でも毎回同じ出力になるとは限りません。ただし、出力の差をすべてtemperatureだけで説明できるわけではありません。サービス側の設定、モデル更新、追加コンテキストなども結果に影響します。

## 7. 選んだトークンを加えて、もう一度予測する

生成処理は選んだトークンを現在の列へ追加し、更新された列から次のトークンを再び計算します。

```text
入力:     [A, B, C]
予測:              D
次の入力: [A, B, C, D]
予測:                 E
```

停止用のトークンが選ばれる、最大出力長へ達する、アプリ側の停止条件に達するなどの条件まで、この処理が続きます。

実際の推論実装では、過去のAttention計算に使うKeyとValueを**KV cache**へ保持し、生成済み部分を毎回すべて計算し直す量を減らす方法が広く使われます。KV cacheは計算を再利用するための一時的な状態であり、モデルのパラメータを学習し直す仕組みではありません。

## 生成は「完成した答えの読み出し」ではない

自己回帰生成では、後半のトークンは、それまでに生成した前半も入力として予測されます。そのため、前半で誤った前提を生成すると、その前提に沿って後半が続くことがあります。

また、モデルが高い確率を付けた文章と、その文章が外部世界で正しいことは同じではありません。確率は、モデルの学習と現在の入力に基づく次トークンの分布です。事実確認の結果を表す確率ではありません。

この性質は[なぜLLMは間違えるのか](./なぜLLMは間違えるのか.md)につながります。

## コンテキスト設計との関係

モデルが毎回参照するのは、利用可能な現在のコンテキストです。既存コードの型定義、失敗したテスト、変更条件を渡せば、それらは次トークンを計算する条件に入ります。無関係な長いログや古い仕様を一緒に渡した場合も、それらは同じ入力列に入ります。

したがって、LLMへ渡す情報を選ぶ作業は、単なる「プロンプトを短くする工夫」ではありません。モデルが次の出力を条件付ける材料そのものを選ぶ作業です。
