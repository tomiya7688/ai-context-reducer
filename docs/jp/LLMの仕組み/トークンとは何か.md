# トークンとは何か

LLMへ「10,000文字の文書を渡す」と言っても、モデルが10,000個の文字をそのまま処理しているとは限りません。LLMを使うシステムは、文章やコードを**トークン**という単位へ分け、各トークンを数値のIDへ変換してからモデルへ渡します。

トークンを理解すると、同じ文字数でもコンテキスト使用量が違う理由や、コード・日本語・英語で入力量の感覚がずれる理由を説明できます。

## トークンは単語とも文字とも限らない

トークン化を行う仕組みを**トークナイザー**と呼びます。トークナイザーは、文字列をモデルが扱う語彙の単位へ分けます。

説明用の例では、次のように分かれると考えられます。

```text
文字列:  context reduction
例:      ["context", " reduction"]
```

別の文字列では、長い単語が複数の断片へ分かれたり、句読点や空白が別のトークンになったりします。日本語では、単語境界を空白で示さないため、英語と同じ感覚で「1単語 = 1トークン」と数えることはできません。

実際の分割規則はモデルごとに使うトークナイザーで異なります。この文書の例は、特定モデルの固定の分割結果を示すものではありません。

## なぜ単語をそのまま使わないのか

すべての単語を一つずつ語彙へ登録すると、人名、専門用語、活用形、綴りの違い、新しい識別子などのために語彙が非常に大きくなります。反対に、すべてを1文字ずつ扱うと、一つの意味を表すために長い列が必要になります。

多くのトークナイザーは、その中間として**サブワード**と呼ばれる単位を使います。頻繁に現れる文字列は比較的大きな単位で持ち、珍しい文字列はより小さな単位へ分けられます。SentencePieceは、空白で事前分割していない生の文からサブワードモデルを学習できる方式の一例です。

## モデルが受け取るのはトークンID

トークナイザーは、分割した各トークンを語彙表のIDへ変換します。Transformerは文字列そのものではなく、トークンIDから作られた数値表現を入力として処理します。

```text
文字列
  ↓ トークナイザー
トークン列
  ↓ 語彙表
トークンID列
  ↓ 埋め込み表現へ変換
Transformer
```

ここでいう**埋め込み表現（Embedding）**は、各トークンIDをモデル内部で扱えるベクトルへ変換したものです。ベクトルは複数の数値を並べた表現で、後続の層はこの数値表現を更新していきます。

埋め込み以降の処理は[Transformerの中では何が起きているのか](./Transformerの中では何が起きているのか.md)で扱います。

## 同じ文字数でもトークン数は同じではない

トークン数は、文字数だけで決まりません。使用する言語、記号、空白、コード中の識別子、トークナイザーの語彙によって分割結果が変わります。

たとえば、次の二つが同じ文字数に近くても、同じトークン数になるとは限りません。

```text
ユーザー設定を保存する
save_user_preferences()
```

コードでは、記号やインデントも入力に含まれます。長いログ、生成物、圧縮されていないJSON、重複したコードを大量に渡すと、それらもトークンとしてコンテキストを消費します。

したがって「100行だから軽い」「日本語で短く書いたから必ず少ない」とは判断できません。正確な数を知りたい場合は、対象モデルと同じトークナイザーや、利用サービスが表示する使用量で確認します。

## トークン数とコンテキストウィンドウ

モデルが一度の処理で扱えるトークン列には上限があります。この上限を[コンテキストウィンドウ](./コンテキストウィンドウとは何か.md)と呼びます。

会話型のサービスでは、利用者が見える本文だけでなく、システム指示、過去の会話、ツール結果などがモデル入力へ含まれる場合があります。生成する出力が同じ上限にどう数えられるかは、モデルとAPIの仕様によって異なります。

そのため、コンテキスト上限を考えるときは「貼り付けた本文の文字数」ではなく、最終的にモデルへ渡るトークン列を考える必要があります。

## トークンを減らすこと自体が目的ではない

トークン数を減らせば、入力コストや処理量を下げられる場合があります。しかし、変更条件や関連テストまで削ると、モデルが判断に必要な情報を失います。

このリポジトリでは、トークン削減そのものを最終目的にしません。まず今回の作業に必要な仕様・コード・テストを特定し、重複や無関係な情報を渡さないことで、必要な根拠へ使えるコンテキストを残します。

次に、トークン列から実際に文章が生成される流れは[LLMが文章を生成するまで](./LLMが文章を生成するまで.md)で確認できます。
