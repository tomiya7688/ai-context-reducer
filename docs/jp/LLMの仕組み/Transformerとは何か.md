# Transformerとは何か

「LLMはTransformerでできている」と聞いても、Transformerが何を解決する構造なのかが分からなければ、LLMの挙動までは説明できません。

Transformerは、トークン列の各位置が他の位置の情報を取り込みながら表現を更新するためのニューラルネットワーク構造です。2017年の論文 *Attention Is All You Need* で、機械翻訳用のEncoder-Decoder構成として提案されました。

現在の生成LLMで使われる構成は、元論文の構造をそのままコピーしたものとは限りません。特に、GPT系のような自己回帰型LLMでは、TransformerのDecoder側の考え方を使った**Decoder-only Transformer**が広く利用されています。

## Transformer以前にあった課題

文章は順序を持つデータです。以前から使われていたRNN系のモデルは、前の時点の状態を次へ渡しながら系列を処理します。この方式では系列の順番に沿った計算が必要になりやすく、長い系列を大規模に学習するときの並列化に制約があります。

元のTransformerは再帰的な計算を使わず、Attentionを中心に系列中の位置同士を直接関連付ける構造を採用しました。元論文では、この構造が従来の再帰・畳み込みを使う翻訳モデルより並列化しやすいことが重要な利点として示されています。

ここで重要なのは「Transformerは長文を完全に理解する魔法」ではなく、**系列中の情報を関連付けて変換する方法を、大規模に学習しやすい形で提供した**ことです。

## Transformerブロックが行うこと

生成LLMを単純化すると、入力トークンは次のように処理されます。

```text
トークンID
  ↓
埋め込み + 位置の情報
  ↓
Transformerブロック
  ├─ Self-Attention
  └─ Feed Forward Network
  ↓
Transformerブロック
  ↓
...何層も繰り返す...
  ↓
次トークン候補のスコア
```

**Self-Attention**は、ある位置の表現を更新するとき、その位置が参照できる他の位置からどの情報をどの程度取り込むかを計算します。

**Feed Forward Network**は、Attentionで混ぜた各位置の表現を、その位置ごとにさらに非線形変換します。

実際のTransformerブロックにはResidual connectionやNormalizationもあり、モデルによって層の順番や位置情報の方式などが異なります。[Transformerの中では何が起きているのか](./Transformerの中では何が起きているのか.md)では、これらを処理順に分解します。

## Attentionがあると何が変わるのか

たとえば、次の文章をモデルへ渡したとします。

```text
設定を保存した。アプリを再起動すると、その設定が消えた。
```

後半の「その設定」を処理するとき、モデルは前半の「設定」との関係を利用する必要があります。Self-Attentionは、このようなトークン位置同士の関係を学習可能な計算として扱います。

ただし、Attentionの重みを見れば人間の意味理解がそのまま読めるわけではありません。Attentionは層ごと・headごと・位置ごとに計算される内部量であり、単一の「重要度ランキング」ではありません。

詳しくは[Attentionとは何か](./Attentionとは何か.md)で扱います。

## Decoder-only Transformerは未来を見ない

文章生成では、次のトークンを予測するときに、本来まだ存在しない未来の正解を参照できてはいけません。自己回帰型のDecoder-only Transformerでは、各位置が自分より後ろの位置を参照しないように**因果マスク（causal mask）**を適用するのが一般的です。

学習時には、正解となる長いトークン列を一度に用意しつつ、因果マスクによって各位置から未来を見えなくします。そのため、複数の位置について次トークン予測を並列に計算できます。

推論時には未来の正解が存在しないため、モデルは実際に一つずつトークンを生成します。この学習と推論の違いは[学習と推論の違い](./学習と推論の違い.md)でも説明します。

## TransformerだけではLLMにならない

Transformerはモデルの**構造**です。構造だけを用意しても、文章やコードを生成できるLLMにはなりません。

大量のデータから次トークン予測を学習し、モデルの多数のパラメータを調整することで、言語モデルとしての能力が作られます。さらに、チャット向けモデルでは指示へ応答するための追加学習が行われることがあります。

つまり、現在のLLMは次の要素を分けて考える必要があります。

```text
Transformerという構造
  + 学習データ
  + 学習目的
  + モデル規模と計算量
  + 必要に応じた追加学習
  = 利用できる言語モデル
```

このつながりは[TransformerからLLMが生まれるまで](./TransformerからLLMが生まれるまで.md)で詳しく説明します。

## コンテキスト削減との関係

Transformerが入力列中の位置同士を関連付けるからといって、コンテキストへ入れたすべての情報が常に同じ精度で利用されるわけではありません。長い入力で関連情報の位置を変えると性能が変化する例も研究されています。

そのため、「コンテキストウィンドウに収まるなら全部入れる」という考え方と、「作業に必要な根拠を選ぶ」という考え方は別です。このリポジトリでは、Transformerが入力から情報を利用することを前提にしつつ、作業に関係する原典へ入力を絞る方法を扱います。
