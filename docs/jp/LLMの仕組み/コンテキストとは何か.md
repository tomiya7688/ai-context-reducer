# コンテキストとは何か

「さっきの関数を直して」と頼めるのは、LLMがその関数を永久に覚えたからでしょうか。「次」と一言送っただけなのに、大きな入力使用量が表示されるのはなぜでしょうか。

**コンテキストとは、モデルが今回の出力を生成するときに、条件として使える情報です。** 指示、会話、コード、資料、ツールの結果などが該当します。ここでは、文章をトークン列として受け取り、続きを生成する自己回帰型のLLMを中心に説明します。トークンはモデルが文章を扱う単位で、必ずしも一文字や一単語ではありません。[1]

この文書では、情報を用意するアプリと、その情報から出力を計算するモデルを分けて追います。容量の上限は[コンテキストウィンドウとは何か](コンテキストウィンドウとは何か.md)、処理や料金は[コンテキストの量と計算量と料金の関係](コンテキストの量と計算量と料金の関係.md)で扱います。

異なる作業の長い会話を引き継がない実践的な方法は、[作業ごとにAIの役割とチャットを分ける](../AI利用/作業ごとにAIの役割とチャットを分ける.md)を参照してください。保存された履歴と、モデルが今回実際に受け取る情報は区別します。

## なぜ指示だけでなく、前提となる情報が必要なのか

架空の二つのアプリで「保存した設定が再起動後に消えるので直して」と依頼するとします。

| アプリ | 現在の実装 | 修正前に必要な確認 |
| --- | --- | --- |
| A | 設定をJSONファイルへ保存する | 保存先と、起動時に読み込むファイルが一致するか |
| B | 設定をデータベースへ保存する | 書込みを確定しているか、起動時にどの値を取得するか |

これは説明用の例であり、不具合の原因を確定したものではありません。同じ依頼文でも、実装と確認方法は異なります。モデルが一般的なJSONやデータベースの使い方を学習していても、それだけでは**今回どちらの実装を直すのか**は決まりません。

そこでアプリや利用者が、現行の実装、守る仕様、関連テストをモデルへ渡します。自己回帰型のモデルは、それらを含む現在のトークン列から、次に続くトークンの候補を計算します。「修正して」という指示も、対象のコードも、この計算の条件です。[1][2]

コードが違えば条件が変わり、生成される変更案も変わり得ます。逆に、違いを示す情報がどこにも与えられなければ、モデルには今回のプロジェクトを区別する根拠がありません。不足を推測で埋めず、ファイルを取得するか、不足している情報を報告する必要があります。

つまり、コンテキストは回答に添える飾りではありません。**一般的な能力を、今回の具体的な作業へ結び付けるための入力**です。

## 誰が何をモデルへ渡しているのか

チャットやコーディングエージェントでは、利用者が送った一文だけが入力になるとは限りません。モデルを呼び出すアプリが、必要な情報を集め、会話の役割や区切りを含む形式に組み立てます。[1][3]

| 入力に含めるもの | 用意する側の例 | モデルへ伝えること |
| --- | --- | --- |
| システムやプロジェクトの指示 | サービス、開発者、利用者 | 守る条件、許可された作業 |
| 今回の依頼と完了条件 | 利用者 | 何を変え、何を確認するか |
| 選ばれた会話履歴や作業メモ | アプリ | 既に決めたこと、現在の状態 |
| コード、仕様、テストの本文 | ファイル取得機能、利用者 | 今回の判断に使う原典 |
| ツールの説明 | アプリ | どの操作を、どんな引数で頼めるか |
| 検索結果、エラー、テスト結果 | 実行したプログラム | 候補の場所や、実際に観測した結果 |

この表は入力の構成例です。すべてのサービスが全項目を毎回含めるという意味ではありません。文章以外を扱うモデルでは、画像や音声などの表現も入力へ加わり、数え方も別途確認が必要です。

例えば「次」の前に、アプリが課題一覧と前回の作業結果を付ければ、モデルはその前提から次の作業を選べます。画面で新しく打った文字は少なくても、**今回組み立てられた入力全体は短いとは限りません。**

## モデルはコンテキストをどう使うのか

文章を受け取った後の基本的な流れは次の通りです。[1][2]

1. **トークナイザーが文章をトークンIDへ変える。** 語句や記号を、モデルが扱う単位と番号へ変換します。
2. **モデルが各IDを数値列へ変える。** この数値列をベクトルと呼びます。位置の情報も使い、どの語句がどの順番にあるかを処理へ反映します。
3. **Transformerが各位置の数値列を更新する。** Attentionという処理では、参照できる位置同士の関係を計算し、他の位置の情報を組み合わせます。
4. **生成処理が次のトークンを選ぶ。** 最後の位置の表現から候補のスコアを計算し、生成方法に従って一つを選びます。
5. **選んだトークンも条件にして続きを作る。** 既に生成した回答部分が、その後の生成にも関係します。

これは、入力の文章を保管しておくだけの処理ではありません。渡された内容を計算し、次の出力の条件に組み込む処理です。詳しくは[LLMが文章を生成するまで](LLMが文章を生成するまで.md)を参照してください。

なお、コードを入力に含めたことは、コードを実行したことではありません。テストの実行はアプリ側のプログラムが行い、その結果をモデルへ返します。モデルが「成功した」と文章を生成しただけでは、実際に成功した証拠になりません。

## 「保存されている」と「今回使える」は別

LLMを使うときの「記憶」には、異なる仕組みが混ざりがちです。

| 場所 | 何があるか | 今回の生成との関係 |
| --- | --- | --- |
| 学習済みのパラメータ | 学習によって調整された、計算に使う数値 | モデルの一般的な出力の傾向や能力を支える |
| アプリに保存された会話やメモ | 過去の文章、作業記録 | 必要な情報を今回の処理へ渡す仕組みが別に必要 |
| リポジトリなどの外部ファイル | 現在のコードや仕様 | 本文を取得して渡さなければ、その本文を参照したことにならない |
| 現在のコンテキスト | 今回の生成に使える指示や資料 | その場の次トークン予測の条件になる |

通常の推論では、会話を一回行うたびにモデルのパラメータを学習し直すわけではありません。推論中の状態と学習の違いは[学習と推論の違い](学習と推論の違い.md)で説明します。

アプリが履歴を残していても、今回渡す際に一部を省略したり、要約へ置き換えたりすれば、画面にある過去の本文と今回の入力は違います。サービスが過去の応答IDを受け取り、サーバー側で履歴を引き継ぐ方式もあります。通信で全文を送り直さないことと、モデルの処理対象から過去情報が消えることは別です。[3]

したがって「前に添付した」「同じチャットにある」だけで、現在も細部を参照できるとは判断しません。重要な判断では、参照した版・箇所を確認し、必要なら原典を再取得します。

## 外部プログラムが調べた量と、LLMが受け取った量

検索プログラムが千個のファイルを検索し、候補のパスを三つ返したとします。この時点でLLMへ渡るのは、返された候補情報です。千個分の本文をLLMへ入力したことにはなりません。

次にアプリが候補ファイルの必要箇所を取得し、その本文をモデルへ返して初めて、本文が次の生成の条件になります。パスだけなら「本文を探す場所」を伝えた段階です。以下は処理の分担を示す例です。

```text
利用者: 設定保存の不具合を直してほしい
モデル: 設定保存に関係する場所の検索を要求する
検索プログラム: ファイル群を調べ、候補のパスを返す
モデル: 必要な候補の本文取得を要求する
取得プログラム: コード・仕様・テストの該当箇所を返す
モデル: 受け取った根拠から変更案を生成する
```

検索にも実行時間や費用がかかる場合があります。ただし、その負担とLLMへ入力するトークン量は分けて記録します。この分離が、先に検索して必要な部分だけ渡す方法の基礎です。

## 「コンテキスト使用量」は何を数えているのか

同じ呼び方で別の数字を示すと、減らす対象を取り違えます。

| 数える対象 | 答えられる問い |
| --- | --- |
| 一回の入力トークン数 | 今回どのくらいの入力を渡したか |
| 一回の出力トークン数 | 今回どのくらい生成したか |
| 現在の処理で使う容量と上限 | 追加の資料や出力をどれだけ扱えるか |
| 複数回の入力・出力の累積量 | 作業全体でどのくらい利用したか |

例えば同じ2,000トークンを三回の入力に含めたなら、その部分の累積入力は6,000トークンです。6,000トークンを同時に保持している、という意味ではありません。これは数え方の仮例であり、料金はキャッシュなどの区分も含めて別に計算します。

内部の推論用トークンを含む出力や、容量の具体的な扱いはモデルごとの仕様に従います。[3] 使用量表示を見るときは、一回の量か累積量か、総数か内訳かを確かめてください。

**コンテキストを減らすとは、まず、今回の生成の条件に含める情報を選ぶことです。** 燃料のような独立した何かを消費する、という理解から始めない方が、容量・計算・料金の違いを追いやすくなります。何を残すと品質を保ちやすいかは[コンテキストの量と使われ方](コンテキストの量と使われ方.md)へ進んでください。
