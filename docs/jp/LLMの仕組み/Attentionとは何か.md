# Attentionとは何か

Attentionは、Transformerの説明で頻繁に出てくる言葉です。「重要な単語へ注目する仕組み」と説明されることがありますが、その一言だけでは実際の計算と誤解が生まれます。

Self-Attentionは、あるトークン位置の表現を更新するとき、その位置が参照できる他の位置からどの情報をどの程度取り込むかを、学習した数値変換を使って計算する仕組みです。

## Attentionは人間の視線ではない

Attentionの重みは、「モデルが人間と同じ意味でここを重要だと思った」という説明ではありません。重みは、特定の層、特定のhead、特定のQuery位置について計算される内部量です。

同じ入力でも、層やheadが違えば別のAttentionが計算されます。したがって、Attentionの重みを一つ取り出して「このモデルが文章全体で重要視した単語の順位」と解釈するのは正確ではありません。

## Self-Attentionで使うQuery・Key・Value

各位置の入力ベクトルから、モデルは学習済みの変換を使ってQuery（Q）、Key（K）、Value（V）を作ります。

- **Query**は、現在位置から参照先を照合するための表現です。
- **Key**は、各参照先がQueryとどの程度対応するかを計算するための表現です。
- **Value**は、対応度に応じて現在位置へ取り込まれる情報です。

「QueryでKeyを検索してValueを取る」という比喩は流れを覚える助けになります。ただし、実際のSelf-Attentionが辞書や検索インデックスを検索しているわけではありません。Q・K・Vはいずれもニューラルネットワーク内部のベクトルです。

## 参照の重みは位置ごとに計算される

説明用に、入力を次のようにします。

```text
保存した設定が再起動後に消えた
```

「消えた」に対応する位置の表現を更新するとき、その位置のQueryは、参照できる各位置のKeyと照合されます。そのスコアから重みを作り、各位置のValueを重み付きで混ぜます。

この計算によって、現在位置は離れた位置の情報を直接取り込めます。RNNのように一つ前の状態を順に受け渡すだけで関係を運ぶ必要はありません。

Scaled Dot-Product Attentionの詳しい処理順は[Transformerの中では何が起きているのか](./Transformerの中では何が起きているのか.md)で説明しています。

## 因果マスクは未来のトークンを隠す

自己回帰型LLMでは、次トークン予測の学習中に未来の正解を見てはいけません。そこで、現在位置より後ろへAttentionを向けられないように**因果マスク**を使います。

たとえば、学習データが次の並びだとします。

```text
A B C D
```

Cの位置から次を予測するとき、モデルはA、B、Cに基づいて予測し、正解側にあるDをAttentionで参照できないようにします。

因果マスクがあるため、学習時に長い列をまとめて計算しても、「未来の答えを見て次を当てる」という不正な学習を防げます。

## Multi-Head Attentionは複数の関係を並行して学べる

Multi-Head Attentionは、Q・K・Vの投影を複数組に分け、それぞれでAttentionを計算します。各headの結果は結合され、次の処理へ渡されます。

複数headを使うことで、同じ入力から異なる表現空間の関係を並行して扱えます。ただし、「head 1は主語、head 2は目的語」のように、人間が固定の役割を割り当てているわけではありません。

## Attentionがあっても長文を完全には使えない

入力がコンテキストウィンドウ内に収まっていれば、Attentionの計算上は参照可能な位置が増えます。しかし、参照可能であることと、必要な情報を常に正しく取り出して回答へ使えることは別です。

*Lost in the Middle* では、複数文書質問応答とKey-Value検索の実験で、関連情報を長い入力のどこへ置くかによって性能が変化しました。調査したモデルでは、関連情報が入力の先頭や末尾にある場合より、中ほどにある場合に性能が下がる傾向が観察されています。

この研究結果から「すべてのモデルは必ず中央を読めない」と一般化することはできません。ただし、**コンテキストへ入れたという事実だけでは、その情報を同じ精度で利用できる保証にならない**ことを示す例です。

## Attentionとコンテキスト削減

コンテキスト削減では、Attentionの重みを利用者が直接操作して「この資料だけ読ませる」わけではありません。利用者は、モデルへ渡すトークン列そのものを選びます。

必要な仕様、関連コード、テスト結果を選んで渡すと、モデルが判断に使う候補を作業に関係する情報へ寄せられます。反対に、古い仕様、重複した説明、無関係なログを一緒に渡すと、それらもTransformerが処理する入力に含まれます。

この考え方は[コンテキストの量と使われ方](./コンテキストの量と使われ方.md)で、実際の作業へつなげます。
