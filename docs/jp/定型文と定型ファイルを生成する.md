# 決まった文章やファイルをひな型から作る

毎回ほぼ同じ形で作る文章や設定ファイルは、共通部分をひな型に残し、作業ごとに変わる値だけを入れて作れます。AIに毎回全文を作り直させずに済み、項目の抜けや意図しない書き換えを防げます。

## 例：リリース案内を作る

リリースのたびに、製品名・版・日付・変更点を載せた案内を作るとします。見出しや項目の順番が毎回同じなら、共通の形をひな型にしておきます。

```markdown
# {{product}} {{version}}

公開日: {{date}}

## 変更点
{{changes}}
```

新しい案内を作るときは、今回の製品名・版・日付・変更点を渡して埋めます。AIにはひな型と今回の値だけを渡せばよく、過去の案内を毎回読み比べたり、同じ見出しを作り直したりする必要がありません。変更点の内容や公開日が正しいかは、生成後に担当者が確認します。

## ひな型と入力値を分ける

ひな型には、毎回変わらない文章・見出し・設定項目を置きます。入力値には、今回の名前・版・日付・対象など、作業ごとに変わるものを置きます。どちらも同じファイルへ複製して別々に直すと、共通部分の修正漏れが起きやすいため、変更元は一つにします。

```text
ひな型 + 今回の入力値 -> 作成した文章・ファイル
```

生成された文章やファイルは利用する成果物です。ひな型を変更したい場合は、生成物を直接直すのではなく、ひな型を直して必要な成果物を作り直します。これで次回も同じ書式を使えます。

## 作成と確認

1. 同じ形式の成果物を何度も作っていることを確認します。
2. 変わらない部分と、毎回入れ替える値を分けます。
3. ひな型と入力値から文章やファイルを作ります。
4. 必須項目が埋まり、置換用の印が残っていないことを確認します。
5. 内容の正しさや承認が必要な場合は、生成結果を担当者が確認します。

生成処理が成功しても、内容まで正しいとは限りません。必須の項目が空でないか、誤った値を入れていないか、必要な見出しがあるかを確認します。ひな型からライセンス文や契約文を作る場合、生成器は承認済みの文章を再利用するだけです。法律上の妥当性や個別案件への適合を判断しません。

意味が重要な公開文書や規約では、どの版のひな型から作ったか、どの入力値を使ったかを追えるようにします。単純な社内メモなどでは、版管理を追加する必要がないこともあります。

## いつ使うか

通知、リリース案内、共通ヘッダー、定型設定など、同じ項目や文章を何度も作る場合に向いています。共通部分はひな型に残し、依頼では今回変わる値だけを指定するため、AIへ毎回過去の例や全文を渡す量を減らせます。生成後は今回の値と差分を確認します。

一度きりで自由な文章や、作業ごとに構成そのものが変わるものには向きません。ひな型を作って維持する手間が、同じ形式を繰り返し作る手間を上回るなら、通常の文章作成で十分です。

## 生成器を使う

入力値を置き換えるだけなら、簡単なスクリプトで足りる場合があります。既にプロジェクトで使っているひな型管理ツールがあり、作成済みプロジェクトへの更新なども必要なら、その仕組みを再利用します。方法を成立させるために特定のツールを導入する必要はありません。

このリポジトリの簡易生成器について、コマンド、置換規則、確認方法は[templateのREADME](../../tools/common/medium/template/README.md)を参照してください。

## AIへの依頼例

> 指定した正本のひな型と今回の入力値だけを使って成果物を生成してください。過去の成果物を読み直して形式を推測しないでください。生成後、必須項目・置換漏れ・今回の入力値との差分を示してください。
