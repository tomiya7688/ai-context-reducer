# AIに作業ルールを整えてもらう

このページの文章をAIに送り、プロジェクトで作業するときに必要な指示書を整えます。最初から全資料を読ませず、実際に繰り返し困っていることを一つ選んで改善します。

## AIへ送る文章

```text
このプロジェクトでAIが必要な情報を見つけやすくするため、AI向けの指示書を整えてください。

最初にREADME、すでにあるAI向け指示書、文書の見出し、テスト方法を確認してください。最初から全ファイルや全履歴を読まないでください。

次を短く調べてください。
- 作業のたびに探し直しているファイルや説明
- 関係のないファイルや長いログを何度も読んでいる場面
- 変更によって必要なテストや確認が変わるか
- すでにある指示書や検索ツールで解決できるか

繰り返し起きている困りごとを一つ選び、最小の修正を提案・実施してください。新しい文書を作る前に、既存の指示書へ短く追記できないか確認してください。

指示書には、AIにどの資料をいつ読ませるか、どの条件で調査範囲を広げるか、何を終わりと判断するかを具体的に書いてください。例を使う場合は、実際のファイル名やテスト名を示すか、架空の例だと明記してください。

プロジェクト全体の入口となる指示書は、リポジトリ直下に `AGENTS.md` という名前で作ってください。機能や制限をまとめる場合は、同じ場所に `PROJECT_CONTEXT.md` を作り、`AGENTS.md` に「どんな作業で読むか」とそのパスを書いてください。繰り返し使う手順や一覧を `docs/` に置く場合も、必要な作業からたどれるよう `AGENTS.md` にリンクしてください。今回だけの条件は指示書に残さず、作業依頼へ書きます。

変更後は、その指示書に従えば必要な資料や確認方法へたどり着けるか確かめてください。関係する自動確認やテストを実行し、確認できなかったことは未確認と報告してください。

最後に、変更したもの、選んだ困りごと、その方法を選んだ理由、確認結果を短く報告してください。効果が見込めない仕組みは追加せず、追加しなかった理由を示してください。
```

## 何を調べてもらうか

小さなプロジェクトなら、README、既存のAI向け指示書、テスト方法、今回の困りごとを見れば十分な場合があります。大きな一覧や専用の自動処理を作るのは、同じ検索や確認を何度も繰り返している場合に限ります。

選ぶ判断の例:

- 毎回同じコードとテストを探すなら、作業ごとの指示書を追加する。
- 大量のログを何度も渡しているなら、必要な行だけを報告するよう指示書に書く。
- テストがすぐ終わり、実行するテストが分かりやすいなら、一覧を作らず既存のテストを実行する。

## なぜ最初に範囲を決めるのか

AIに読む場所と確認方法を最初に伝えると、プロジェクト全体の検索結果や関係のない説明を受け取らずに作業を始められます。必要な情報が見つからない場合は追加で探すよう指示するため、短く始めても確認不足にはしません。

## 用語

「コンテキスト」は、AIに一度に渡す指示、コード、文書、確認結果などの情報です。コンテキスト削減では、その中から作業に必要な情報を残し、関係のない情報を省きます。
