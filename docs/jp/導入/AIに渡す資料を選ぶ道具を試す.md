# AIに渡す資料を選ぶ道具を試す

AIに不具合修正を頼む前に、プロジェクトの概要と、使えそうな調査方法を表示してみましょう。ここでは、補助ツールをダウンロードし、最初の結果を得るまでを説明します。小さなプロジェクトなら、目安は5分です。ダウンロードや調査にかかる時間は、回線やプロジェクトの大きさで変わります。

## 1. 配布物を選んで展開する

[最新の配布ページ](https://github.com/tomiya7688/ai-context-reducer/releases/latest)を開きます。公開済みの v1.0.0 は、コマンドを入力して使う通常版です。ページの「Assets」から、自分のOSとCPUに合う圧縮ファイルを選んでください。「Source code」は、以下の手順で使う実行ファイルの配布物ではありません。

| OS | CPUの種類 | v1.0.0 のファイル名の末尾 | 圧縮ファイルのサイズ |
|---|---|---|---|
| Windows | x64 | `windows-x64.zip` | 5.1 MiB |
| Windows | arm64 | `windows-arm64.zip` | 4.7 MiB |
| Linux | x64 | `linux-x64.tar.gz` | 4.8 MiB |
| Linux | arm64 | `linux-arm64.tar.gz` | 4.4 MiB |
| macOS | x64 | `macos-x64.tar.gz` | 4.8 MiB |
| macOS | arm64 | `macos-arm64.tar.gz` | 4.5 MiB |

サイズは[公開済み v1.0.0](https://github.com/tomiya7688/ai-context-reducer/releases/tag/v1.0.0)の添付ファイルの値を MiB（1,048,576バイト）へ換算し、小数第1位に丸めたものです。

CPUの種類が分からなければ、Windowsでは「設定 → システム → バージョン情報」の「システムの種類」を確認してください。Linux・macOSでは、ターミナルで `uname -m` を実行し、`x86_64` なら x64、`aarch64` または `arm64` なら arm64 を選びます。

ダウンロードしたファイルを展開してください。この手順で使う概要表示と操作案表示には、配布済みの実行ファイルを使うため、Python・Goなどの言語環境の追加インストールは不要です。別の詳しい解析を使う場合は、その解析に必要な環境を個別に確認します。[v1.0.0 の配布検証記録](../../../release/validation/v1.0.0.md)も参照できます。

## 2. 展開したフォルダーで実行する

コマンドを入力できる画面を開き、`acr-toolbox` があるフォルダーを作業場所にします。Windowsでは、エクスプローラーでそのフォルダーを開き、アドレス欄に `cmd` と入力して Enter を押せます。Linux・macOSでは、ターミナルを開き、`cd "/展開したフォルダーの場所"` で移動してください。

以下のプロジェクトのパスを、調べたいフォルダーの場所に置き換えて実行します。展開先ではなく、コードが入ったプロジェクトのフォルダーを指定してください。

Windows:

```text
.\acr-toolbox.exe analyze "C:\path\to\your-project"
.\acr-toolbox.exe select "C:\path\to\your-project"
```

Linux・macOS:

```text
./acr-toolbox analyze "/path/to/your-project"
./acr-toolbox select "/path/to/your-project"
```

`analyze` は言語やファイル数などの概要を表示します。`select` は、その概要から次に試せる調査方法を提案します。どちらもコードの正しさを判定したり、提案したテストや解析を自動実行したりするコマンドではありません。

## 3. 今回の作業に関係する操作だけを見る

結果は、項目名と値を対応づけた JSON という形式で表示されます。最初は次の項目を見てください。

| 表示される項目 | 見る内容 |
|---|---|
| `status` | `ok` なら調査成功。`ok_with_warnings` なら一部の読み取りに問題があり、必要なファイルが抜けていないか確認します。 |
| `project_root` | 自分が指定したプロジェクトを調べたか確認します。 |
| `language_file_counts` | どの言語のファイルがあるか確認します。 |
| `recommended_tools`・`conditional_tools` | 試せる操作の一覧です。各項目の `reason` は提案理由、`activation` は使う場面、`availability` は利用条件を示します。 |

たとえば「設定を保存する処理」を探したいなら、検索の提案から始められます。今回関係のない文書整理や別言語の解析まで、まとめて実行する必要はありません。

検索を試す場合は、展開先から次のように実行できます。`save` と `src` の場所は、探したい名前とプロジェクトのソースフォルダーに置き換えてください。

Windows:

```text
.\acr-toolbox.exe search --max-results 20 "save" "C:\path\to\your-project\src"
```

Linux・macOS:

```text
./acr-toolbox search --max-results 20 "save" "/path/to/your-project/src"
```

検索結果のファイル名と行番号を手掛かりに、AIに関係するコードとテストを読ませます。関係のないファイルの本文を丸ごと渡す量を抑えられます。検索結果だけで原因を決めず、見つかったコードや仕様で確かめさせてください。

## 4. 結果をAIへ渡す

普段使うAIへ、作業内容と、今回関係する概要・検索結果を貼り付けるか添付します。次の依頼文を今回の作業に合わせて使えます。

```text
作業内容: 設定を保存しても再起動すると元に戻る不具合を直してください。
対象フォルダー: [プロジェクトの場所]

添付した概要と検索結果から、設定の保存処理・起動時の読み込み・関連テストを調べてください。
関係するコードと仕様を読んで修正し、保存した設定が再起動後も保たれるか確認してください。
情報が足りなければ、必要な場所を追加で探してください。
最後に、変更内容、実行した確認と結果、確認できなかったことを報告してください。
```

チャットだけでコードを読めないAIには、検索で見つかったコード・仕様・テストも添付してください。

## 困ったとき

- **コマンドが見つからない**: 展開したフォルダーの中で、`acr-toolbox.exe` または `acr-toolbox` がある場所を作業場所にしてください。
- **起動できない**: OSとCPUの種類に合う圧縮ファイルか確認してください。OSがダウンロードしたアプリの確認を求めた場合は、配布元とファイルを確認してから、そのOSの案内に従ってください。
- **`input_missing`・`input_not_directory` と出る**: 指定したパスにプロジェクトのフォルダーがあるか確認してください。空白を含むパスは例のように引用符で囲みます。
- **`scan_failed`・`ok_with_warnings` と出る**: エラーや読み取れなかった箇所を確認し、今回必要なファイルを別の方法で調べてください。
