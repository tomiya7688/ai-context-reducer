# AIに作業を頼むときの基本手順

AIに修正を頼むときは、目的と終わりの目安を伝え、関係する資料・コード・テストを確認してもらいます。この文書では、一つの作業を始めて終えるまでの基本手順を説明します。

## まず、作業の終わりを決める

例として、「設定画面に言語選択を追加する」作業を考えます。始める前に、次のことを決めます。

- **目的:** 設定画面から表示言語を選べるようにする。
- **守ること:** すでに保存されている設定を壊さない。
- **確認する場所:** 設定画面と、設定を保存する処理。
- **完了の目安:** 選んだ言語が保存され、アプリを開き直しても選択が残る。関係するテストも通る。

この4つが分かれば、まず関係する場所だけを調べます。別の疑問が出たら、その疑問に必要な情報だけ追加で確認します。

## 情報の種類ごとに、見る場所を選ぶ

| 知りたいこと | まず見る場所 |
|---|---|
| プロジェクトの概要 | `README` |
| 作業のルール | AI向けの作業指示書 |
| 今できること・できないこと | プロジェクトでできることと制限をまとめた文書 |
| 仕様や約束 | 詳細な設計文書 |
| 実際の動き | プログラムとテスト |
| 作業の目的や順番 | 作業依頼や未完了作業の一覧 |
| 生成されたファイルやログ | 必要になったときだけ確認 |

同じ内容の説明が食い違ったら、その決まりを正式に説明する文書を確認します。実際の動きは、プログラムとテストで確かめます。

## 必要なファイルを見つける

1. ファイル名や言葉で検索する。
2. 検索で見つかったファイルのうち、今回の作業に関係する資料を読む。
3. 大きなファイルは、必要な部分から読む。

最初から全ファイルを開く必要はありません。生成物、ログ、古い履歴も、今回の作業に関係しなければ読みません。ただし、動作確認に必要なファイルは除外しないでください。

## 調べるのを止める

次が分かり、作業を始められる状態になったら、広い範囲の検索を止めます。

- 何を変えるか
- 何を守るか
- どのファイルを確認するか
- 何をもって完了とするか

作業や確認の途中で分からないことが出たら、その点についてだけ調べ直します。

## 作業メモは今回限りにする

複数日にまたがる作業では、目的、変更する場所、守ること、確認方法を短いメモにまとめると便利です。このメモは作業を引き継ぐためのものです。正式な仕様書の代わりにしたり、同じ説明を別の文書へコピーしたりしないでください。

## 決めたことを保存し、AIに読ませる場所

何をどこへ書くかは、その情報を使う期間で決めます。

| 情報 | 書く場所 | AIへの渡し方 |
| --- | --- | --- |
| 今回だけの目的、変更範囲、完了条件 | 今回の依頼文 | 依頼文に直接書く。数日にまたがるなら、ひな型から `CONTEXT_PACK.md` を作り、AIへの依頼でそのパスを伝える。作業後は今回限りのメモを片づける。 |
| 毎回守る作業ルール | リポジトリ直下の `AGENTS.md` | 利用中のAIが自動で読むか確認する。自動で読まない場合は、依頼で `AGENTS.md` を読むよう伝える。 |
| プロジェクトの機能や制限 | リポジトリ直下の `PROJECT_CONTEXT.md` | `AGENTS.md` から参照し、関係する作業ではこのファイルも読むようAIに伝える。 |
| 繰り返し使う手順や資料一覧 | `docs/` 内の目的が分かる名前の文書 | `AGENTS.md` に文書へのリンクと「どんな作業で読むか」を書く。今回関係する場合だけAIに開かせる。 |

たとえば、作業別の確認先を `docs/変更別の確認先.md` にまとめたら、`AGENTS.md` に「変更の種類ごとの最初の確認先は `docs/変更別の確認先.md` を参照」と書きます。文書を置いただけではAIが読むとは限りません。AIへの入口となる指示書からリンクするか、依頼文でパスを指定してください。詳しい指示書の置き方は[AIに作業場所に合った指示書を読ませる](AIに作業場所に合った指示書を読ませる.md)、ひな型は[AIへの作業ルールのひな型](../../../templates/README.md)を参照してください。

## 必要な仕組みだけ足す

小さなプロジェクトなら、短い指示書と検索だけで十分なことがあります。毎回同じ場所を探すようになったら、作業ごとに読む資料の一覧やファイルの役割表を追加します。こうした一覧や自動化は、同じ場所を探し直す手間が、作成や手入れの手間を上回るときだけ使います。詳しくは[必要な方法だけ選ぶ](../導入/必要な方法だけ選ぶ.md)を参照してください。

## 変更を確かめる

変更の種類に合ったテストや確認を行います。画面の変更なら必要に応じて実際の画面を確認し、配布物を変えたなら配布用ファイルも確認します。実行したテストが0件だった場合など、対象を確認できていない結果は成功の根拠になりません。

確認できていないことは、確認済みのように書かず、「未確認」と伝えます。

## 避けること

- 関係のない修正を一緒に行う。
- 同じ説明を何か所にもコピーする。
- 小さなプロジェクトに、使わない表や一覧を増やす。
- 確かめていないことを推測で埋める。

## AIへの指示例

```text
作業ルールとして、リポジトリ直下の AGENTS.md を確認してください。
機能や制限の確認が必要なら PROJECT_CONTEXT.md を読み、今回の変更に関係する資料だけをそこからたどってください。

今回の依頼:
設定画面に言語選択を追加してください。
設定を保存する処理と関連テストを確認し、選択した言語が再起動後も残ることを確かめてください。

依頼の目的、守る条件、完了の目安を確認してください。
最初は関係する資料、コード、テストだけを探して読んでください。
必要な情報が足りないときは、何が分からないかを示し、その疑問に答える資料だけ追加で調べてください。
変更後は関係する確認を行い、未確認のことを分けて報告してください。
```

この順に必要な情報を選んでAIへ伝えると、全資料を読ませて目的を推測させずに済みます。読む情報を減らす場合も、作業の判断に必要なコードや確認は省かないでください。
