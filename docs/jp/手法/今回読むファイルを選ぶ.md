# 今回読むファイルを選ぶ

変更する場所がすぐに分からなくても、プロジェクトのファイルを全部読む必要はありません。今回の作業に関係するものから確認します。

## 例：保存したデータを読み込めない

この不具合を直すなら、まず次を確認します。

1. データを読み込むプログラム
2. 保存してから読み込めるか確かめる動作確認
3. 保存データの決まりを書いた文書
4. 必要なら、そのデータを使う別のプログラム

画面を表示するファイルがプロジェクトで一番大きくても、この不具合に関係しなければ読む必要はありません。

## 大きいファイルを見つけたら

関係するファイルが大きい場合は、最初から全部読まず、次の順で範囲を狭めます。

1. 関係する名前や言葉を検索する。
2. 見つかった部分と、その前後を読む。
3. それだけでは判断できない場合に、読む範囲を広げる。

必要な情報が大きなファイルに書かれているなら、サイズを理由に読み飛ばしてはいけません。必要な部分を探して確認します。

本文自体が一度に読める量を超える場合は、[長いファイルやログを区切ってAIに渡す](長いファイルやログを区切ってAIに渡す.md)で、区切り方と確認済み範囲の記録を確認してください。読むファイルの選定と、選んだ本文の渡し方を分けて扱います。

## AIへの指示例

```text
まず作業に近いコード、説明、テストから確認してください。
大きなファイルでは、関係する言葉や処理名を検索し、その前後を読んでください。
根拠が足りないと分かったときだけ、読む範囲を広げてください。
```

## なぜ読む量が減るのか

ファイルの大きさではなく、作業との関係で順番を決めるため、巨大な無関係ファイルを最初から読む必要がありません。関係する記述がその中にある場合は、検索して必要な部分を読みます。
