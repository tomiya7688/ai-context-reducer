# 繰り返し使う文書や設定をひな型から作る

ライセンス文、通知文、設定ファイルなど、毎回ほぼ同じものを作る場合は、共通部分をひな型として一か所に置き、名前や日付など変わる情報だけを入れて作ります。

## 作り方の例

```text
ひな型:
  {{名前}} は {{利用条件}} で使用できます。

今回入れる情報:
  名前 = Example
  利用条件 = 商用利用可能
```

生成した後は、変わる情報が正しく入ったか、未入力の記号が残っていないか、必要な段落があるかを確認します。法的な内容やプロジェクトの決まりが正しいかどうかは、作成結果だけで判断せず、承認済みの文面を確認してください。

## ひな型と入力値を分ける

ひな型には、毎回変わらない文章・見出し・設定項目を置きます。入力値には、今回の名前・版・日付など、作業ごとに変わるものを置きます。同じ内容を別々のファイルに複製すると共通部分の修正漏れが起きやすいため、変更元は一つにします。

生成された文書やファイルは利用する成果物です。ひな型を変えたいときは、成果物を直接直さず、ひな型を直して必要な成果物を作り直します。意味が重要な公開文書や規約では、どの版のひな型から、どの入力値で作ったかを追えるようにします。単純な社内メモなどでは、版管理を足す必要はありません。

## AIへの指示例

```text
既存のひな型を探し、その名前と今回変える値だけを使って文書を作ってください。
ひな型の共通部分を書き直さず、生成した文書に未入力の項目がないか確認してください。
変更した値、使用したひな型、確認結果を報告してください。
ひな型そのものを変更する必要がありそうな場合は、生成文書を直接書き換える前に、ひな型の担当者と内容を確認してください。
```

## なぜ読む量が減るのか

ひな型と変更する値をAIに渡せば、全文を毎回読み直したり書き直したりさせず、生成結果の差分を確認させられます。共通部分が一つにまとまるため、文面の揺れや項目の抜けも減らせます。

## 使う目安

同じ形式のファイルを繰り返し作る、全文の書き直しで誤りが起きる、複数の場所の文面をそろえる必要がある場合に使います。作成が一度きりなら、ひな型や生成の仕組みを増やす必要はありません。

## どこに保存し、AIにどう読ませるか

繰り返し使うひな型は `templates/` に目的が分かる名前で保存します。ひな型を使う作業をAIに頼むときは、依頼文にひな型のパスと、完成した文書を保存するパスの両方を書いてください。複数の人が何度も使うなら、その手順を `AGENTS.md` または `docs/` 内の作業案内からひな型へリンクします。ひな型を置いただけでは、AIが自動で使うとは限りません。

## 用語

- **Template Generation / boilerplate generation**: 共通部分をひな型に残し、変わる値だけを入れて文書やファイルを作る方法を、このように呼びます。

## 補助ツール

- 必要なら、`acr-toolbox template`がひな型の `{{名前}}` などを指定した値に置き換えてファイルを作ります。定型の文書や設定を作るときに使えます。作成前の確認や、未入力項目の検出もできます。

プロジェクトに別のひな型作成ツールがあれば、その仕組みを再利用できます。
