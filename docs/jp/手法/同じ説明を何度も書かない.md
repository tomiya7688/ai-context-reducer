# 同じ説明を何度も書かない

同じ仕様や決まりを複数の文書に全文で書くと、読む量が増え、更新後に内容が食い違います。詳しい説明を一つの文書に置き、他の文書には「何の説明か」とリンクだけを残します。

## どの文書を元にするか決める

たとえば、保存データの形式を `docs/data-format.md` で決めたなら、READMEやAI向け指示書には次のように書きます。

```text
保存データを変更するときは、形式の説明と互換性の条件を確認する。
詳しい決まり: docs/data-format.md
```

「元にする文書」は、その決まりを正式に説明する場所です。同じ決まりを別の文書にコピーした場合は、片方だけ直して食い違う可能性があります。

## AIに元の文書を見つけさせる

元の文書を決めたら、他の説明書やAI向け指示書から相対リンクを付けます。たとえば保存形式の決まりを `docs/data-format.md` に置いた場合、保存処理を変えるときにAIが読む `AGENTS.md` へ「保存形式を変える場合は `docs/data-format.md` を確認」と書きます。一度だけの作業では、依頼文に元の文書のパスを直接書けば十分です。

## AIへの指示例

```text
今回の作業に関係する説明が複数の文書にないか確認してください。
同じ詳しい決まりが重複していたら、どの文書を正式な説明にするか決め、他の文書には短い説明とリンクを残してください。
短い概要、使用例、安全上必要な注意書きは、読む人がその場で理解するために必要なら残してください。
似た文章を見つけただけで自動削除せず、変更後も必要な情報へ移動できるか確認してください。
```

## 何を残し、何をまとめるか

- READMEには、初めて使う人が迷わない短い説明と詳しい文書へのリンクを残す。
- AI向け指示書には、いつ何を読むかを短く書き、詳細の全文は貼らない。
- 複数の場所から参照する決まりは、正式な説明を一つ選ぶ。
- 注意書きや、その文書だけで使う短い説明は、必要なら繰り返してよい。
- 配布物の中で単独で読む必要がある文書は、必要な説明を残す。

要約や一覧に詳しい決まりを新設しないでください。要約と正式な説明が違う場合は、正式な説明を確認して要約を直します。

## なぜ読む量が減るのか

詳しい説明を一か所にまとめてAIに渡せば、同じ長文を複数の文書から読ませずに済みます。更新後に複数のコピーを探して比べる作業も減ります。必要な資料へのリンクを書けば、文書を短くしても説明そのものは失われません。

## まとめる目安

同じ詳しい決まりを複数個所で更新している、あるいは説明が食い違っているなら、元にする文書を一つ決めます。文書が少なく、重複による更新漏れもないなら、専用の一覧や自動処理は作りません。短い概要だけの重複は、読者の助けになるなら残します。

## 補助ツール

- 必要なら、`doc-duplicate-hints`が似た説明のある文書を一覧にします。重複している説明を探すときに使えます。AIに各文書の役割とリンクを確認させてから、残す説明や整理する箇所を決めてください。
