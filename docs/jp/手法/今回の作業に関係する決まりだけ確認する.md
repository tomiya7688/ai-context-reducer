# 今回の作業に関係する決まりだけ確認する

プロジェクトに決まりがたくさんあっても、AIに毎回すべて読ませる必要はありません。今回直す機能に当てはまる決まりを先に選び、背景や詳しい説明は判断に必要なときだけ確認します。

## 例：日付の不具合を直す

あるアプリには、次の決まりがあるとします。

- 保存済みデータの形式は変えない。
- 画面のボタンには説明を付ける。
- 新しい画面は青系の色にする。

表データから読んだ日付が1日ずれる問題を直すなら、まず「保存済みデータの形式は変えない」を確認します。画面のボタンや色の決まりは、今回の修正に画面変更がなければ読む必要はありません。

## 必ず守る決まりと、目安を分ける

決まりには、違反してはいけないものと、通常は従うが理由があれば変えられるものがあります。両者を区別せずAIに渡すと、推奨事項まで絶対の禁止事項として扱ったり、本当に必須の条件を見落としたりすることがあります。依頼には、それぞれの強さも書いてください。

| 種類 | 意味 | 例 |
| --- | --- | --- |
| 必須 | 守らなければ変更を受け入れられない | 保存済みデータの形式を壊さない |
| 推奨 | ふだんは従う。変えるときは理由を示す | 既存の画面部品を再利用する |
| 参考 | 判断の助けにする。違反と決めつけない | 過去に同じ不具合が起きた場所 |

## 関係する決まりを探す

1. 作業依頼から、変える機能やファイルを確かめる。
2. その機能に当てはまる必須の決まりを確認する。
3. 今回の判断に役立つ推奨や背景だけ追加で読む。
4. 自動確認の結果があれば、今回の変更に関係するものを確認する。

自動確認に通っても、すべての決まりを守れたとは限りません。自動で判断できない決まりは、人が関係するコードや説明を確認するか、作業を頼んだAIに確認させてください。

## 例外を認めるとき

必須の決まりを今回だけ変える必要がある場合は、作業メモに「どの決まりの例外か」「なぜ必要か」「どの範囲に限るか」を書き、元の決まりへのリンクを残します。例外を関係のないファイルや将来の作業へ広げません。

## AIへの指示例

```text
今回変更する機能を確認し、当てはまる必須の決まりを先に読んでください。
判断に必要な推奨事項や背景だけを追加で確認し、関係のない決まりは読まないでください。
必須の決まりを変える必要がある場合は、理由と対象範囲を示して、変更前に報告してください。
```

## なぜ読む量が減るのか

作業に当てはまらない画面や機能の決まりを毎回読まずに済みます。必須の決まりは先に確認し、例外が必要な場合も理由と範囲を確認するため、守る条件まで読み飛ばすことを防げます。

## 用語

- **必須の決まり**: 守らないと変更を受け入れられない条件です。
- **推奨事項**: ふだんは従う方がよい決まりですが、理由があれば変えられます。
- **自動確認**: プログラムで決まりを調べ、違反の可能性や問題箇所を表示する仕組みです。
