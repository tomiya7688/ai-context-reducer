# AIに調査を止めさせる条件を決める

調査を始める前に、問題を再現する入力、原因を調べるコードの場所、修正後に確認する正しい結果を決め、AIへの依頼に書きます。AIには、この3点が分かったら追加のファイル検索を止めて修正に進み、分からない点が残った場合だけ、その点を確かめられる場所を調べるよう伝えます。

## 例：読み込んだ日付が1日ずれる

表データを読み込むと、4月10日が4月9日と表示される不具合を直すとします。次の内容が確認できたら、いったん調査を止めて修正へ進みます。

1. 問題が起きる入力を再現できる。
2. 日付を読み込むコードの場所が分かる。
3. 同じ入力で正しい日付になることを確かめる方法がある。
4. 修正後に4月10日と表示されれば直ったと判断できる。

この不具合を直すだけなら、日付に関する説明書を全部読んだり、過去の変更をすべて確認したりする必要はありません。

## 次の3つが分かったら、調査を止める

- **何を直すか:** 今回の作業内容。
- **どこを確認するか:** 関係するコード、テスト、説明書。
- **どうなれば終わりか:** 修正後の動きや確認結果。

調査の前に一行ずつAIへの依頼に書いておくと、必要な場所を確認させたか判断しやすくなります。

```text
直すこと: 読み込んだ日付が1日ずれる不具合
確認する場所: 日付を読むコードと、その動作を確認するテスト
終わりの目安: 同じ入力で4月10日と表示される
```

## 分からないことが残るなら、そこだけ調べる

次のような場合は、調査を続けます。

- 問題を再現できず、原因を特定できない。
- コードとテストの結果が食い違っている。
- 直した場所が別の機能にも影響する。
- 何をもって直ったと言えるか決まっていない。

追加の調査では、残っている疑問に答えられるファイルだけを確認します。たとえば日付を読むコードから別の処理が呼ばれていると分かったら、その呼び出し先を調べます。疑問が解決したら、また修正や確認へ進みます。

## 今回やらないことも決める

頼まれた修正と関係のない機能や改善まで、調査・変更の範囲を広げないようにします。必要なら作業メモに「今回は画面の見た目を変えない」のように書きます。後で行う必要があることは、別の作業依頼に残します。

調査を止める条件は今回の依頼文に書きます。同じ条件を何度も使う場合だけ、リポジトリ直下の `AGENTS.md` や `docs/` 内の作業案内へ移し、どの作業で使うかを記します。一度の不具合のために新しい指示書を作る必要はありません。

## 確かめていないことは、そのまま伝える

完了を判断するのに必要な確認ができない場合は、できたように扱わず、何を確認できていないか報告します。すべての不明点をなくすためだけに調査を続ける必要はありません。今回の修正に必要な点だけ確認します。

## AIへの指示例

```text
目的、確認する場所、完了の目安を先に確認してください。
この3点が分かり、作業を始められるなら、全体検索を止めて修正してください。
途中で判断に必要な疑問が出たら、その疑問に答える場所だけ調べてください。
確認できなかったことは完了したように扱わず、未確認と報告してください。
```

## なぜ読む量が減るのか

完了の目安を先に決めると、目安を満たした後に資料を読み続けなくて済みます。新しい疑問が出たときだけ調査を再開するため、関係のない情報を追加で渡しません。

## 用語

- **調査を止める目安**: どの情報がそろったら、追加の検索を終えて修正や動作確認に進むかを決めたものです。
- **テスト**: 同じ入力でプログラムを動かし、期待した結果になるかを繰り返し確かめる仕組みです。
