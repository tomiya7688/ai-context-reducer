# AIに読む情報を絞る3つの方法

「設定の保存がうまくいかないので直して」とAIに頼む場面を考えます。AIにプロジェクトの全ファイルを読ませると、関係のない画面や資料まで混ざり、必要な場所を見つけにくくなります。このページでは、読む量を減らすための3つの方法を説明します。

AIには、作業に必要な情報を選んで渡します。方法は次の3つです。

1. **機械で分かることは、先に機械で調べる。**
2. **何度も行う手順は、決めて使い回す。**
3. **関係する部分だけAIに読ませる。**

## 1. 機械で分かることは先に調べる

設定を保存する処理を直すなら、まず検索や開発用の道具で、その処理が書かれた場所、呼び出す場所、関連するテストを探します。AIには、その結果のうち今回必要なものを渡します。

検索結果をAIに渡すと、全ファイルを読ませて名前やつながりを推測させる手間を減らせます。ただし、機械の結果だけで修正内容を決めず、必要なコードやテストはAIにも確認させます。

プログラムを実際に動かさず、コードの書き方やファイル間のつながりを調べる方法もあります。これは読む場所を探すために使い、動作やビルドの正しさは別に確認します。

## 2. 何度も行う手順は決めて使い回す

検索、関連ファイルの確認、テストの選択など、毎回同じ順番で行う作業は、短い手順や小さな道具にまとめてAIに渡します。こうすれば、AIに毎回やり方を考え直させずに済みます。

ただし、手順や道具を増やすことで、準備や手入れの手間が増えるなら導入しません。同じ作業が繰り返され、まとめることで手間が減るときに使います。

## 3. 関係する部分だけAIに読ませる

設定の保存を直すなら、まず保存処理とそのテストを確認します。別の画面や関係のない過去の記録は、必要になった場合だけ調べます。

短い一覧や要約は、必要なファイルを見つけるために使います。内容を決めるときは、実際の説明書、コード、テストを確認します。一覧や要約だけを根拠にしてはいけません。

## 新しい方法や道具を選ぶとき

それが次のどれを減らすのかを確認します。

- AIがコードから推測していたこと
- AIが毎回繰り返していた手順
- AIが読む必要のなかったファイルや説明

どれにも当てはまらないなら、本当に作業の手間が減るのか考え直します。小さなプロジェクトなら、検索と短い指示書だけで十分なことがあります。

## 正確さを保つ

目的は、AIにできるだけ少なく読ませることではありません。必要な情報をきちんと渡し、関係のない情報を減らすことです。判断に必要な根拠まで省かないようにします。

## AIへの指示例

```text
作業の目的と完了条件を確認し、関係するコード・資料・テストから調べ始めてください。
必要な情報がない場合は、その疑問に答える資料だけ追加で調べてください。
どこを確認し、何を確認できなかったかを最後に報告してください。
```

## なぜ読む量が減るのか

この指示では、AIに作業の目的と完了条件を伝え、関係する資料から調べ始めるよう頼みます。必要な情報が足りないときだけ調査範囲を広げるため、全ファイルを最初から読ませずに済みます。

## 用語

- **コンテキスト**: AIに渡す指示、コード、資料、検索結果、確認結果など、回答を作るための情報です。
- **静的解析**: プログラムを動かさずに、コードの書き方やつながりを調べることです。場所を探す助けになりますが、正しく動くことまでは証明しません。
