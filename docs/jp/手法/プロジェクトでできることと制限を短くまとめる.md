# プロジェクトでできることと制限を短くまとめる

あなたがAIにコードの修正を頼むとき、AIが**今使える機能・まだ使えない機能・守る条件**を知らないと、以前の説明やコードを何度も探すことがあります。あなたは、この三つを既存のREADMEに数行で書いておけます。READMEが長くなるなら、別の短いメモにしても構いません。

このメモは、AIへ現在の前提を伝えるためのものです。詳しい仕様やコードの全文を書き写す必要はありません。

## 例：表データを読む機能

例えば、あなたのアプリに次の機能があるとします。説明用の架空の例です。

```text
今できること：表データの読み込み
制限：日付は文字として扱い、時刻帯の変換はしない
未対応：表計算ソフト専用のファイル形式は読み込めない
詳しい決まり：docs/date-format.md
```

あなたは現在のコードと仕様を確認してから、このように書いてください。`docs/date-format.md` は例示用の名前なので、実際にはあなたのプロジェクトの説明書の場所に置き換えます。

## メモに何を書くか

あなたは、繰り返し調べ直している内容から、次の情報を選んで書いてください。

- 今使える主な機能
- 機能を使う際の制限・守る条件
- まだ使えない機能
- 詳しい仕様・実装・テストを確認できる資料の場所

すべての機能や過去の作業記録を並べる必要はありません。今回の作業だけの条件は、[作業ごとのメモ](今回の作業に必要なことを短くまとめる.md)や依頼文へ書いてください。

## メモを作る方法

あなたは既存のREADMEに数行を追加するだけで始められます。専用の補助ツールや追加のプログラムは必要ありません。

別ファイルを使いたい場合は、[プロジェクト情報のひな型](../../../templates/PROJECT_CONTEXT.md)を `PROJECT_CONTEXT.md` という名前であなたのプロジェクトのルートにコピーできます。すべての項目を埋める必要はありません。

AIにメモを自動で読ませたいなら、あなたが使っているAIの指示書（例：`AGENTS.md`）に、必要な作業でこのメモを読むよう書いてください。**AIがその指示書を自動で読むとは限らない**ため、使っている製品の設定を確かめてください。自動で読まない場合は、依頼文でメモの場所を伝えられます。

## AIにメモを使わせる

**次は、あなたがAIに送る依頼文の例です。**

```text
まず、今使える機能と制限を書いたメモを確認してください。
今回の依頼に関係する箇所だけを手掛かりに、必要なコードとテストを調べてください。
詳しい仕様はメモに書かれた元の資料を確認してください。
メモと元の資料やコードが食い違う場合は、推測せず食い違いを報告してください。
```

AIがファイルを開けない場合は、あなたが必要なメモと元資料をAIに渡してください。AIに古い記述を正しいものとして扱わせないため、あなたはAIの回答と現在の仕様・コード・テストを照らして確認してください。

## 機能や制限が変わったら

あなた、または更新を許可されたAIが、変更した機能に関係する記述を直します。あなたは修正後のメモが現在の仕様と動作を正しく表しているか確認してください。

短いメモが役立つのは、同じ前提を繰り返し調べている場合です。一度限りの小さな作業や、既存のREADMEで十分に分かる場合は、新しいメモを作る必要はありません。
