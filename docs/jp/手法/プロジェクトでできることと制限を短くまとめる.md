# プロジェクトでできることと制限を短くまとめる

作業を始める人がまず知りたいのは、「今できること」「まだできないこと」「守る条件」です。これを短いメモにしておくと、毎回READMEや過去の依頼・議論を探し直さずにすみます。

このメモは詳しい説明書や今回の作業指示の代わりではありません。詳しい説明が必要なときに読めるよう、元の資料の場所も記します。

## 例：架空の表データ読み込み機能

> 表データの読み込みに対応しています。日付はそのままの文字として扱います。表計算ソフト専用のファイル形式には対応していません。日付の詳しい決まりは `docs/date-format.md` を確認してください。

この例では、対応している形式、日付の扱い、まだ使えない形式を短く伝えています。`docs/date-format.md` は説明用の架空の資料名です。

## 書いておくこと

- 今使える主な機能
- 使うときの制限や条件
- まだ使えない機能
- 必要なら、今後の作業で特に重要な目標

詳しい仕様や個別の作業内容はここに写さず、元の説明書や作業依頼に書きます。

## ほかの文書との使い分け

- README：プロジェクトの概要や使い始め方
- AI向けの指示書：作業時に守る決まりや、読む資料の場所
- このメモ：今使える機能、制限、未対応の機能
- 作業ごとのメモ：今回頼まれた内容
- 説明書やコード：詳しい仕様と実際の動き

## 内容が変わったら直す

機能の追加や制限の変更があったら、このメモも更新します。説明書や実際の動きと食い違うときは、説明書やコードを確認してからメモを直します。

書き始めるときは[プロジェクト情報のひな型](../../../templates/PROJECT_CONTEXT.md)をリポジトリ直下へ `PROJECT_CONTEXT.md` という名前でコピーします。すべての項目を埋めず、何度も調べ直している事実だけを残してください。AIがこの情報を見つけられるよう、リポジトリ直下の `AGENTS.md` に「プロジェクトの機能や制限を確認するときは `PROJECT_CONTEXT.md` を読む」と書きます。AIが `AGENTS.md` を自動で読まない場合は、依頼文で両方のパスを指定してください。

## AIへの指示例

```text
このプロジェクトでできることと制限をまとめたメモを、今回の作業を始める前に確認してください。
関係する仕様や動作が分からない場合は、記載された説明書とコードを確認してください。
メモと実際のコードが食い違っていたら、コードとテストを確認し、作業後にメモを直してください。
```

## なぜ読む量が減るのか

このメモをAIに渡すと、READMEや過去の作業記録から機能や制限を探し直させずに、作業の前提を伝えられます。詳しい仕様や実際の動きは元の資料をAIに確認させるため、長い説明を重ねて保存する必要はありません。
