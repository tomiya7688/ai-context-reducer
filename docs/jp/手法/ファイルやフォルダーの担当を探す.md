# ファイルやフォルダーの担当を探す

ファイル名だけでは、どこに何が書かれているか分からないことがあります。そんなときは、まず仕事の種類ごとに大きく分け、それぞれの担当範囲を示します。全ファイルを一つずつ書き出す表ではありません。主要な仕事の種類ごとに、関係するフォルダーや代表的な場所をまとめます。

## 例：支払い済みなのに督促メールが届く

請求書の支払いが済んでいるのに、支払いを求めるメールが届く不具合を直すとします。次の表は、架空の請求アプリを例にしたものです。

| 仕事の種類 | 主な場所 | 担当 |
| --- | --- | --- |
| 請求と支払い | `src/invoices/` | 請求書と、支払い済みかどうかを記録する |
| 督促 | `src/reminders/` | 支払いが済んでいない請求書を選び、督促メールの内容を作る |
| メール送信 | `src/email/` | メールを送る |
| 動作確認 | `tests/reminders/` | 支払い済みの請求書には督促メールを作らないことを確かめる |

この不具合なら、まず「督促」の行にある `src/reminders/` と「動作確認」の行にある `tests/reminders/` を見ます。督促メールを作る条件と、その条件を確かめる方法が分かるからです。支払い済みかどうかの情報が間違っていそうなら「請求と支払い」を、正しいメールが作られているのに届かないなら「メール送信」を調べます。

このように、問題の内容に合わせて調べる場所を選べます。すべてのファイルを開いて担当を推測する必要はありません。

## 役割表の作り方

仕事の種類を先に決め、その仕事を担当する主なフォルダーや場所だけを載せます。細かなファイルや関数をすべて並べる必要はありません。担当が変わったときは、表の説明も合わせて直します。

小さなプロジェクトなら、別の表を作らず、すでにあるAI向け指示書に数行足すだけで十分です。表が実際のコードと違っていたら、表を信じずコードを確認してください。

何度も使う役割表は、たとえば `docs/ファイルの担当表.md` に保存し、リポジトリ直下の `AGENTS.md` から参照できるようにします。依頼では、AIに「問題に関係する行から読み、表で判断できない場合だけ範囲を広げる」と伝えてください。既存の資料一覧や変更別の確認先に同じ担当情報があるなら、別表は作らず既存の一覧へまとめます。

## AIへの指示例

```text
問題の内容に合う担当を表から選び、その場所のコードと動作確認を最初に見てください。
表の担当だけでは原因を説明できない場合は、関係する別の担当も調べてください。
表と実際のコードが違っていたら、作業後に表も更新してください。
```

## なぜ読む量が減るのか

ファイル名だけを見て役割を推測したり、一つずつ開いたりする手間を省けます。必要な担当から調べ始め、原因が別の担当にあると分かったときだけ範囲を広げます。
