# AIに普段読ませないファイルを決める

アプリの修正をAIに頼むとき、作業と関係のないログや一時ファイルまで渡す必要はありません。普段AIに読ませないものを決め、必要なコードやテストの場所を依頼で伝えてください。

ここで決めるのは、作業中にAIへ読ませる範囲です。ファイルを削除したり、共有先から除いたりする設定とは別です。

## 普段はAIに読ませないものを決める

次のようなファイルやフォルダーは、作業に関係しないことが多いため、普段はAIに読ませない設定を検討します。

- アプリを作るときにできる実行ファイルや出力ファイル
- 動作記録、調査記録、大きなログ
- ダウンロードした外部ライブラリ
- 一時ファイルやキャッシュ
- 作業用の保存データやバックアップ
- 今回の作業と関係のない古い変更履歴
- エディターや開発ツールが自動で作ったファイル

フォルダー名だけを理由にAIへ読ませないと決めないでください。「生成物」や「ログ」でも、そのプロジェクトでは必要な場合があります。

## 作業に必要なものは読ませる

AIに読ませない設定にする前に、次の点を確認します。

1. そのファイルが仕様や動作の正式な根拠になっていないか。
2. 今回直す対象そのものではないか。
3. 今回の確認やテストに必要ではないか。
4. そのプロジェクトだけで使う大事なデータではないか。
5. 必要なときに作り直す方法が分かるか。

一つでも当てはまるなら、普段は読ませない設定にして終わりにせず、必要な作業ではAIに読ませます。判断がつかないファイルは、除外を確定せず、そのままにします。

### 例: 配布用アプリを確認する

普段の修正では、アプリのコードとテストをAIに読ませ、前回作った配布用ファイルは読ませないことがあります。一方、今回の作業が「配布用アプリが起動するか確認する」なら、その配布用ファイル自体を開いて確認する必要があります。

つまり、同じファイルでも作業によって必要かどうかが変わります。普段読ませない設定は、その作業でも絶対に読ませないという意味ではありません。

## 「読ませない」と「削除する」を混同しない

AIに普段読ませないファイルも、プロジェクトに残ります。`.gitignore` などの設定を変えて、共有や記録の対象から外すこととは別です。

```text
AIに普段読ませない
  → 作業中にAIへ渡す情報を絞る

共有や記録の対象から外す
  → プロジェクトの設定やファイルの扱いを変える
```

ログや生成物を普段読ませないからといって、それらを削除したり、共有対象から外したりする必要はありません。設定を変える場合は、そのファイルが配布やテストに必要でないことを別に確認します。

## ファイルの種類ごとの考え方

| ファイルの種類 | 普段の扱い | 必要になる例 |
| --- | --- | --- |
| アプリを作ったときの出力 | 普段は読ませない | 配布用ファイルが正しく作られたか確認する |
| ログや動作記録 | 関係する部分だけ読む | 不具合が起きた原因を調べる |
| 外部ライブラリ | 普段は読ませない | 外部ライブラリに加えた変更や安全上の問題を調べる |
| 一時ファイルやキャッシュ | 普段は読ませない | キャッシュが原因の不具合を直す |
| 古い変更履歴 | 普段は読ませない | 不具合がいつ始まったか調べる |
| テスト用の見本データ | テストに必要なら読む | そのデータを使って正しさを確認する |

## 小さなプロジェクトなら短く書く

特別な一覧を作らず、プロジェクト全体の指示書に次のように書くだけでも構いません。

```text
普段は読まなくてよいもの:
- 作成時に出る一時ファイル
- 今回と関係のないログ
- 今回と関係のない古い変更履歴

ただし、作業やテストに必要なら該当部分を読む。
```

専用の一覧や自動判定の道具を作るのは、毎回同じ範囲を見分ける手間が大きくなってからで十分です。

すでに `AGENTS.md`、`CLAUDE.md`、`AI_CONTEXT.md` などの案内がある場合は、利用中のAIがそのファイルを読むか確かめてから追記し、同じルールを持つファイルを増やさないでください。除外の決まりが全作業共通ならプロジェクト直下の案内へ、特定の繰り返す作業だけなら対応するAIのSkillsへ置けます。ファイル名・保存場所・自動読込はツールごとに異なります。詳しくは[AIに作業場所に合った指示書を読ませる](AIに作業場所に合った指示書を読ませる.md)を参照してください。

AIが自動で読み込む範囲からファイルを本当に除外するには、使っているAI製品が対応するプロジェクト用の除外設定へ対象パスを書きます。設定ファイル名や保存場所は製品ごとに違うため、その製品の説明で確認してください。`.gitignore` はGitで共有するファイルを決めるもので、AIに読ませない設定にはなりません。除外設定がない場合は、リポジトリ直下の `AGENTS.md` に「通常の調査ではこのパスを開かない。ただし変更やテストに必要なら読む」と書き、AIへの依頼でも伝えます。これはAIへの指示であり、製品の除外設定のように読み込みを防ぐ機能ではありません。

## 除外した場所が作業の対象になったら

ビルド失敗の原因を調べるときは、その失敗に関係するログを読みます。配布物が正しくできたか確かめるときは、配布物の中身を確認します。生成ファイルの問題を直すときは、生成元と生成結果の両方を調べることがあります。

このような作業では、案内やAIツールの設定からその場所を一時的に外すか、必要なファイルだけを明示して読ませます。確認が終わったら、通常の除外設定に戻します。除外は読み飛ばす初期候補を決めるもので、作業に必要な根拠を無視する理由にはなりません。

## AIへの指示例

```text
ログ、一時ファイル、自動生成ファイルは、今回の作業に必要か確かめてから開いてください。
実装、仕様、テスト、配布物の確認に必要なファイルは除外しないでください。
必要か判断できないファイルは除外せず、理由を報告してください。
```

## なぜ読む量が減るのか

作業に関係のないログや生成物を毎回AIに渡さずに済みます。必要なときは対象を戻して確認するため、対象外の設定が正しさを確かめる情報まで隠すことはありません。

## 用語

- **Context Exclusion / ignore rules**: 読み始める候補から外す方針と、その設定を指します。普段の調査から外しつつ、必要な作業では読む方法をこの名前で呼びます。
- **普段はAIに読ませないファイル**: 多くの作業では不要でも、特定の作業やテストでは確認が必要になるファイルやフォルダーです。
- **共有や記録の対象から外す設定**: `.gitignore` など、ファイルを共有・記録する仕組みに関する設定です。AIに読ませる範囲とは別に判断します。

## 補助ツール

- 必要なら、`ignore-candidates`が普段の作業ではAIに読ませなくてもよさそうなファイルを一覧表示します。読み込み対象から外す候補を探すときに使えます。不要かどうかは自動判断せず、ファイルも削除しません。一覧を確認してから設定してください。
