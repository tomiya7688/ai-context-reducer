# 言語に合った解析方法を選ぶ

解析の深さは、知りたい答えに合わせて選びます。解析器が広い範囲を調べても、結果から必要な場所や診断だけを選んでAIに渡せば、AIが全ソースや全ログを読む必要はありません。情報を絞れるのは、解析したからではなく、結果を候補探しに使い、必要な原文だけを渡すからです。

## 例：大きなアプリでCSV取込を変更する

PythonとGoで作られたアプリのCSV取込を直すとします。どこから読むか分からない段階では、まずファイルや関数の候補を探します。変更の影響先やビルドの成否まで知る必要が出たら、その問いに答えられる解析や検査を追加します。

## 何を知りたいかで深さを選ぶ

| 知りたいこと | 使う解析・検査 | AIに渡すものと、読む量が減る理由 |
| --- | --- | --- |
| 対象のファイルや関数 | ファイル名・関数名を探す軽い解析 | 候補の場所を渡す。AIが全ファイルから対象を探す必要がなくなる。実装とテストは原文で確認する。 |
| 呼び出し元や影響先 | ファイル間の参照・依存関係の解析 | 関係する箇所とテストの候補を渡す。AIが全ソースを読んで関係を洗い出す量を減らせる。候補だけで動作を判断せず、選んだ原文を読む。 |
| 型・ビルド・実行結果 | プロジェクトのコンパイラー、開発キット、実行環境で検査 | 成否と関係する診断を渡す。全ログを会話に載せず、必要なエラーから原因を調べられる。 |

軽い解析は実行環境なしで使えることがありますが、場所の候補を示すだけで、動作・型・ビルドの正しさは確かめません。たとえばPythonの実行やC#のビルドには、それぞれの環境や .NET SDK が必要な場合があります。深い解析ほど常に良いわけではありません。必要な根拠が得られたら止め、結果を全件AIに渡さないようにします。

## 既存の環境を使う

まず、プロジェクトの言語と既に使える開発用ソフトを確認します。環境が足りなければ、できる解析だけを行い、未確認の項目を明記します。この調査のためだけに実行環境や開発キットを自動で追加しません。小さなプロジェクトで対象とテストが分かっているなら、専用の解析を挟まず原文を確認します。解析結果やログを全件渡すだけでは、AIの読む量は減りません。

解析の結果は、今回の問いに必要な候補だけを使います。型やビルドの正しさが必要なら、対応する解析器や開発環境が使えるかを確認してください。

## AIへの依頼例

> 今回知りたいことに合う深さを選び、結果から関係する候補だけを返してください。選んだコードとテストを原文で確認し、解析結果の全件や全ログは渡さないでください。実行できなかった確認も明記してください。

## 補助ツール・用語

必要なら[language-setup](../../tools/common/small/language-setup/README.md)が、プロジェクトの言語と利用可能な実行環境を調べ、実行候補を示します。[language-run](../../tools/common/small/language-run/README.md)は対応する軽量解析を実行し、結果をファイルに保存します。用語: **lightweight search / dependency analysis / language-specific analysis**。
