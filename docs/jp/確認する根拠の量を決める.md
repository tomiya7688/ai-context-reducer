# 必要な確認を先に決める

調査を始める前に、今回の判断に欠かせない情報を決めます。必要な情報が分かれば、関係しそうな資料を片端から読む代わりに、不足している点だけを調べられます。確認を終える条件の決め方は[調査を止める条件を決める](探索を止める条件を決める.md)を参照してください。

## 例：請求額の税の端数処理を直す

請求書の税額を丸める位置を変更するとします。作業前に、次の点が分かれば変更を判断できると決めます。

- 仕様上、商品ごとに丸めるのか、合計後に丸めるのか
- 税額を計算する実装箇所
- 端数が出る金額を含む確認方法

まず仕様、税額の計算処理、対応するテストを調べます。これらが同じ丸め方を示していれば、画面全体の説明や過去の請求書機能の議論まで読む必要はありません。仕様と実装が食い違う、またはテストで問題が見つかる場合は、その違いを解決する資料だけを追加で確認します。

## 必要な情報と、後回しにできる情報

何が必要かは作業によって異なります。たとえば、一つの関数の不具合なら、要件、対象の処理、該当するテストで足りることがあります。データ形式の変更なら、読み書きする側や互換性の決まりも必要です。

判断に必要な情報がそろったら、履歴、隣接機能の説明、広い設計資料などは、理由が出るまで後回しにできます。次の検索や読み込みをする前に「何の疑問を解決するためか」を言葉にします。答えられないなら、情報を増やす前に止まれるか考えます。

これは読む回数や文字数を決めて打ち切る方法ではありません。変更から共有機能への影響が分かった、資料どうしが矛盾する、検査に失敗した、情報漏えいやデータ消失につながる不明点が見つかった、といった場合には追加調査が必要です。確かめられない点は確認済みとせず、未確認として残します。

小さく明白な修正に、必要情報の一覧や記録を毎回作る必要はありません。どこまで調べるか迷いやすい作業でだけ、確認事項を短く書き出します。

## AIへの依頼例

> 判断する前に、今回答える必要がある質問と、それぞれに必要な最小限の根拠を挙げてください。質問に答えられる原典とテストを確認し、未解決の問いが残る場合だけ追加で調べてください。確認済みと未確認を分けて報告してください。
