# ふだん読まないファイルを決める

日常的な修正では、作業に関係しにくい生成物、ログ、外部ライブラリのコピー、一時ファイルなどを、最初からAIに読ませないようにします。これらを候補から外しておけば、実装やテストなど必要な情報が埋もれず、毎回読み込む量も減ります。ここで決めるのはAIが通常読む範囲であり、ファイルの削除やGitの除外設定ではありません。

## 例：金額計算の不具合を直す

計算結果が誤る不具合なら、まず計算処理、関連するテスト、仕様を確認します。以前のビルドで作られた実行ファイル、無関係な過去のログ、外部ライブラリのコピー、一時キャッシュは、今回の判断に使わない限り読みません。必要な実装とテストに集中でき、AIが大量の無関係な内容から手掛かりを探さずに済みます。

失敗したビルドの原因を調べる場合は、該当するエラー部分を読みます。配布ファイルそのものが正しいか確かめる作業なら、その配布ファイルを検査します。生成物でも依頼の対象や確認材料になった時点で、必要な範囲だけ読みます。

## 必要になったときだけ読む

生成物は、プログラムや文書から作られた出力です。通常は作り方の原文やコードを先に読みますが、出力結果の確認が目的なら生成物も必要です。ログは、失敗や動作の原因を調べるときに関係する箇所を読みます。外部ライブラリのコピーは、そこへの変更、脆弱性調査、ライセンス確認などが目的の場合に確認します。一時キャッシュは、消去や再作成に関する不具合を調べる場合に対象になります。

## 除外を決めるときの注意

`build`、`generated`、`vendor`などの名前だけでは、読まなくてよいと決められません。生成済みコードが正式な入力だったり、テストデータや配布物が完了確認に必要だったりするプロジェクトもあります。現在の作業に必要な原文や確認材料でないかを確かめ、不明なら候補から完全に外さずにおきます。

AIに通常読ませない設定と、ファイルを削除したり `.gitignore` などを変更したりすることは別です。この案内だけを理由に、ファイルやリポジトリ設定を変更してはいけません。小さなプロジェクトなら、AI向けの案内に「ビルド出力とキャッシュは通常読まない」と短く書くだけで十分です。
