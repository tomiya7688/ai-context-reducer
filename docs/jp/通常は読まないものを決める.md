# ふだん読まないファイルを決める

毎回の調査に関係しないファイルを、AIが最初に探す場所から外す方法です。たとえば、ソースから作り直せるビルド出力や古いログを通常の候補から外すと、AIは必要な処理やテストを見つけやすくなります。必要な資料まで除外しないよう、「何を外すか」と「どんな作業なら読むか」をセットで決めます。

## 何を外すか決める

ファイル名やフォルダー名だけで決めず、次の二点を確認します。

1. そのファイルは、今回の判断や確認に使うか。
2. 使わない場合、同じ情報をソースコードや設定など別の場所で確認できるか。

たとえば、通常の機能修正では、ソースから再生成できる `build/` や `dist/` の出力、再作成できるキャッシュ、今回と無関係な古いログを候補から外せます。外部ライブラリのコピーも、そのライブラリを変更したり調べたりしない作業なら、最初の候補から外せます。

一方、テスト、設定、仕様、入力データ、依存関係の一覧などは、作業によって必要になります。名前が `generated`、`vendor`、`lock` だからという理由だけで、常に除外してはいけません。何に使われているか分からない場合は、除外対象にせず、必要になった時に判断できる状態にします。

## AIに読ませない設定をする

決めた内容を、プロジェクトでAIに作業を頼むときに読む案内へ書きます。すでに `AGENTS.md`、`CLAUDE.md`、`AI_CONTEXT.md` などの案内があるなら、同じルールを重ねて新しいファイルを作らず、その案内に追記します。特定のAIツールだけを使うプロジェクトでは、そのツールが読む指示ファイルを使います。

たとえば、次のように「通常の対象」「除外する場所」「例外」を書きます。

```text
通常のコード調査では、build/、dist/、.cache/ の中身を最初の確認対象から外してください。
これらから作られるファイルを変更・調査する依頼や、ビルド結果・配布物の確認では、必要なファイルだけ読んでください。
```

この書き方は、AIに毎回同じ除外条件を伝える手間を減らします。ただし、案内ファイルに書くだけでは読み取り権限を制限できません。AIがその場所を絶対に読めないようにする必要がある場合は、使っているAIツールやエディターにファイルの除外・アクセス制限機能があるか確認し、同じ場所を設定します。設定が検索結果から隠すだけなのか、パスを指定した直接読み込みも止めるのかは、ツールごとに異なります。

検索コマンドに除外条件を付ける方法もありますが、そのコマンドの結果だけが対象です。`.gitignore` はGitにファイルを追跡させない設定であり、AIや検索ツールから読めなくする設定ではありません。ファイルを消したり、Git設定を変えたりする必要はありません。

## 例外が起きたら

ビルド失敗の原因を調べるときは、その失敗に関係するログを読みます。配布物が正しくできたか確かめるときは、配布物の中身を確認します。生成ファイルの問題を直すときは、依頼内容に応じて生成元と生成結果の両方を調べることがあります。

除外した場所が作業の対象になったら、案内やAIツールの設定からその場所を一時的に外すか、必要なファイルだけを明示して読ませます。確認が終わったら、通常の除外設定に戻します。除外ルールは読み飛ばす初期候補を決めるもので、作業に必要な根拠を無視する理由にはなりません。

小さなプロジェクトでは、AI向けの案内に短い一段落を加えるだけで十分です。除外する場所が多く、何度も手作業で指定している場合に限り、AIツール側のファイル除外設定も整えます。
