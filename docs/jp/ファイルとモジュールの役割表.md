# ファイルとモジュールの役割表

役割表は、主要なファイルやモジュールが何を担当するかを短く記した一覧です。ファイル名だけでは役割が分かりにくいプロジェクトで、ソースを片端から開く前に作業対象の候補を絞るために使います。

## 例: CSVの日付表示を直す

CSVから読み取った日付の表示を直すとします。役割表に「CSV読込は行の分割と値の取り出し」「日付変換は表示形式の統一」と書かれていれば、まず日付変換の実装と対応テストを確認できます。CSV読込や画面など、無関係なファイルをすべて開いて担当を推測する手間が減ります。

```text
| 場所 | 担当 |
|---|---|
| src/import/csv_reader.py | CSVの行を読み、列の値を取り出す |
| src/date/normalize.py | 日付の値を表示用の形式に変換する |
| tests/date/test_normalize.py | 日付変換の動作を確認する |
```

## 役割表の作り方

変更が多い主要なファイルやモジュールを選び、担当を一文で書きます。細かな関数一覧や実装説明は載せず、必要なコードを開くための入口にします。担当範囲が不明な場合は、名前から決めつけず、実装や既存の設計資料を確認します。

役割表は詳しい仕様書ではありません。現在の作業に関係する候補を見つけたら、元のソースやテストを読みます。変更内容から確認先を選ぶ必要がある場合は、[変更内容ごとの案内表](変更内容ごとの案内表.md)も使えます。大きなソースの関数や依存関係まで調べる場合は、[コード構造の索引](コード構造の索引.md)が候補になります。

## 更新と使いどころ

ファイルの主な担当を追加・移動・分割した変更では、役割表も同じ変更で更新します。古い表は誤ったファイルへ案内するため、更新できない表は現在の担当を示す根拠として扱わず、ソースから確認します。

担当とテストが少数ファイルから分かる小規模なプロジェクトでは、専用表を作らず、既存のAI向け案内や設計文書の短い記述で足ります。役割表の更新にかかる時間が、繰り返しの調査を減らす時間より大きい場合も導入しません。

## AIへの依頼例

役割表を作業依頼に添付するか、利用中のAIが実際に読む案内からリンクします。単発なら次のように頼みます。

> 変更内容に関係する担当ファイルとテストを役割表から選び、表の記述と実装が一致しているか確認してください。候補のパスと根拠を示し、担当が分からない箇所だけ原典を追加で調べてください。

## 補助ツール・用語

必要なら[responsibility-candidates](../../tools/common/medium/responsibility-candidates/README.md)で表の下書きを作れますが、担当は人が原典で確認します。この一覧は **Responsibility Map（役割表）** と呼ばれます。
