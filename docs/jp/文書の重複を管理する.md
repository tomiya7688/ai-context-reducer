# 文書の同じ説明を一か所にまとめる

READMEや導入ガイド、AI向けの案内に同じ手順をそれぞれ書くと、読む量が増え、変更時に内容が食い違いやすくなります。詳しい説明を一つの文書に置き、ほかの文書には用途に合った短い案内とリンクを残すと、必要な説明だけを読めて、更新箇所も分かりやすくなります。

## 例：アプリの導入手順

README、導入ガイド、AI向けの案内に、必要なソフトや設定手順をすべて書いているとします。導入方法が変わるたびに三か所を直す必要があり、一つを直し忘れると、どの説明が正しいのか読者にもAIにも判断できません。

たとえば、詳しい手順を `docs/setup.md` にまとめます。READMEには「対応環境と導入手順はこちら」と短く書いてリンクし、AI向けの案内には「導入方法を変更するときはこの手順を確認する」と用途を添えて同じページへ案内します。AIは作業に必要な入口だけをたどり、複製された手順を読み比べずに済みます。手順の更新も一か所で行えます。

## まとめ方

同じ決まりや手順が複数の文書にあると気づいたら、まず各文書が誰に何を伝えるためのものかを確認します。内容と目的が同じなら、詳しい説明を置く文書を一つ決めます。残りの説明は機械的に消さず、読者がその場で必要とする概要を残したうえで、何を知りたいときにどこを読めばよいかを案内します。

たとえば「設定の保存形式と互換性の決まりは `docs/settings-format.md` を参照してください」のように、リンク先だけでなく、読む理由も書きます。これならREADMEだけを読む人にも次の行動が分かり、AIも不要な詳細を先回りして読まずに済みます。

## 繰り返してよい説明

すべての重複をなくす必要はありません。文書を単独で配る場合に欠かせない利用条件や、危険な操作の直前に必要な注意、初めての人が迷わないための短い概要は、それぞれの場所に残します。ただし、詳しい仕様まで丸ごと写すと、再び別々の更新が必要になります。短い説明だけで安全に使えるか、元の説明へ迷わず移れるかを確かめます。

また、似た言葉が出てくるだけで、同じ説明とは限りません。初心者向けの概要と運用担当者向けの手順など、対象や目的が異なる場合は、単純に片方を削らず、それぞれに必要な内容を残します。

## 変更時の確認

詳しい説明を移した後は、残した案内が正しい場所を指しているか、リンクが開けるか、元の文書に必要な概要や注意が残っているかを確認します。文章が似ているという理由だけで自動削除・統合すると、別の読者に必要な説明まで失うことがあります。重複を見つける道具は確認箇所を探すために使い、どれを残すかは文書の目的を見て決めます。
