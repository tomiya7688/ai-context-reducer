# コード構造の索引

コード構造の索引は、関数や型の場所、それらの呼び出し・依存関係を検索できる一覧です。大きなソースコードを最初から読む前に一覧で候補を絞ると、関係する定義やテストから調査を始められます。索引は原文の代わりではなく、読む場所を見つけるために使います。

## 例: 設定読み込み処理を変更する

設定ファイルの読み込み方法を変えるとします。索引で読み込み関数を探すと、その関数を呼び出す箇所や、利用しているモジュールをたどれます。関係するテストも候補にできます。AIにはまず、その関数と直接関係する箇所だけを案内し、必要になった依存先やテストを追加で読んでもらいます。これにより、無関係な画面やライブラリまで先に読む量を減らせます。

```text
変更したい動作
  -> 関係する関数・型を探す
  -> 呼び出し元と関連テストを確かめる
  -> 必要な元コードを読む
  -> 影響が広がる場合は調査先を追加する
```

## 索引に載せる情報

索引には、たとえば次の情報を記録します。

- ファイル、モジュール、型、関数の名前
- 定義があるファイルと行
- 関数が呼び出す先、またはその関数を呼び出す側
- モジュール間の読み込みや依存関係
- 各ファイルやモジュールの担当範囲

プロジェクトで既に使っているIDE、言語ツール、静的解析器が同じ情報を持つなら、それを再利用できます。構文の形を調べる[Tree-sitter](https://github.com/tree-sitter/tree-sitter)や、定義・参照の索引を共有する[SCIP](https://github.com/scip-code/scip)は、その例です。新しい解析器を導入するためだけに環境を増やす必要はありません。

## 索引を使う流れ

1. 依頼内容から、探す名前や変更されたファイルを決める。
2. 索引で定義、呼び出し元、依存先、関連テストの候補を探す。
3. 候補の元ファイルを開いて、実際の処理と関係を確認する。
4. 変更が共通処理や公開仕様に及ぶ場合は、より広い範囲と検証へ進む。

索引に多数の結果があっても、すべてをAIへ渡す必要はありません。作業に直接関係する結果を先に渡し、判断に必要な参照先が分かったら、原文書やソースコードへ進みます。

## 向いている場合と限界

大きなファイルから同じ関数を何度も探す場合や、変更のたびに呼び出し元・依存先・テストをたどる場合に役立ちます。関係する名前やファイルが既に分かっている小さな変更では、通常の検索で十分です。索引の生成や更新に手間がかかり、調査時間を減らさない場合は追加しません。

索引は解析器が分かる範囲の関係しか示しません。動的な呼び出しや生成コードなど、索引に出ない依存がある場合があります。索引が古い場合もあるため、変更前に元コードを確認し、共有処理や公開仕様の変更では必要な広い検証を行います。索引の結果だけで影響範囲や安全性を断定しません。

このリポジトリの[source-structure-index](../../tools/common/large/source-structure-index/README.md)は、関数や型の定義場所、呼び出し元、依存先を索引化し、指定した名前や変更ファイルに関係する候補を返します。詳細はREADMEを参照してください。基本の考え方は、別の索引や検索手段でも導入できます。

## AIへの依頼例

> 索引から対象の関数・型、その呼び出し元や関連テストを検索し、今回関係する候補だけをパスと理由付きで示してください。選んだ元コードとテストを開いて確認し、索引に出ない可能性や未確認範囲も報告してください。

## 補助ツール・用語

[source-structure-index](../../tools/common/large/source-structure-index/README.md)や言語別解析器を使えます。用語: **Source Structure Index / symbol index**。
