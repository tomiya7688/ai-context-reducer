# AIに読み方の仕組みを整えてもらう

この依頼文は、AIにプロジェクトを調べてもらい、繰り返し困っている調査や読み直しを減らすための案内を整えるときに使います。ai-context-reducerの全手法やツールを一括で入れさせるものではありません。まず対象プロジェクトを小さく調べ、実際に起きている手間に合う案内だけを追加します。

## 例：小さなリポジトリと複数アプリ

ファイル数が少なく、設定処理とテストの場所がすぐ分かるプロジェクトなら、最初に読むファイルと実行するテストを短く案内するだけで足ります。コード索引や専用ツールを追加しても、調査時間より整備・更新の手間が増えることがあります。

DesktopとWebを含む大きなプロジェクトで、設定変更のたびに対象の画面・保存処理・テストを探し直しているなら、作業内容から確認先を選ぶ表や、アプリごとの作業ルールが役立つかもしれません。AIに「何をいつも探し直しているか」を先に調べさせ、その繰り返しを減らす仕組みだけ選ぶので、無関係な資料や他アプリのルールを読ませずに済みます。

## 依頼の手順

1. 対象プロジェクトを開き、以下の依頼文をAIに渡します。
2. AIはまず指定した入口と、対象プロジェクトの概要・既存案内・テスト・ビルド情報を確認します。
3. いつも調べ直していることを特定し、既存の案内を直すか、小さな仕組みを一つ追加します。
4. 変更後、対象箇所とテストへ案内から進めるかを確かめ、追加しなかった手法の理由も報告します。

## コピーして使う依頼文

```text
このプロジェクトで、作業のたびに同じ調査や読み直しをしなくて済むように、ai-context-reducer の考え方を必要な範囲だけ取り入れてください。

参考: https://github.com/tomiya7688/ai-context-reducer

最初に読む資料は次の3つです。
- ai-context-reducer の README
- docs/jp/導入優先度.md
- templates/AI_CONTEXT.md

対象プロジェクトは、ルート構成、README、既存のAI向け案内、docsの見出し、テスト、ビルド・配布設定などを入口として確認してください。最初から全ソース・全docs・全Issueを読み通さないでください。

まず、何を毎回探し直しているのか、どの案内が古い・不足しているのかを特定してください。既存の AGENTS.md、CLAUDE.md、README、docs が使えるなら、それを直して再利用してください。

小さなプロジェクトでは、短いAI向け入口と基本ルールだけで止めてください。追加の表・索引・自動化は、繰り返し発生する手間を実際に減らす場合だけ、一つずつ追加してください。導入済みの標準という理由だけで全手法を追加しないでください。

必要な案内を整えたら、そこから対象コード・対応テスト・正式な仕様へ進めることを確認してください。文書のリンクや追加した検証方法も確認し、不確かな点は確定事項のように書かず、未確認として残してください。

最後に次を報告してください。
- 追加・修正した案内と、その理由
- 追加しなかった手法と、その理由
- 確認したテスト・検証
- まだ分からないこと
```

## 導入後に見ること

AIが多くの文書を読んだかではなく、案内から今回の作業に関係するコードやテストへ進めるかを確認します。小さなプロジェクトなら、全体向けの短い入口だけでよい場合があります。大きなプロジェクトでも、追加した表や索引が古くなれば探す手間が戻るため、コードや担当範囲の変更時に更新できる形にします。

導入する手法を選ぶ詳しい目安は[導入優先度](導入優先度.md)を参照してください。プロジェクトの規模や困りごとに応じて、依頼文から不要な指示を取り除いて構いません。

## 補助ツール・用語

この依頼文に専用ツールは不要です。必要な手法が決まってから[手法と補助ツールの対応表](ツールとの対応.md)を参照します。既存の案内をAIの入口にする整備は **Context Engineering / context setup** と呼ばれることがあります。
