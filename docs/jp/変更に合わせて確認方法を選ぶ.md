# 変更に合わせて確認方法を選ぶ

変更した内容が正しく動くと判断するには、確かめたい性質に合った確認が必要です。たとえば計算の変更はテストで確かめられますが、画面の配置が正しいかはテスト成功だけでは分かりません。何を確かめる必要があるかを先に決め、無関係な検査や大量のログを読む手間を省きます。

## 例：CSV読み込み、画面、配布物

CSVの日付変換を直すなら、入力と期待する日付を使ったテストで変換結果を確かめます。画面のボタン位置を変えるなら、画面を起動して配置を目で確かめます。配布設定を変えるなら、開発中のコードがビルドできるだけでは足りず、作成した配布物が起動し必要なファイルを持つことを確認します。

| 変更 | 確かめたいこと | 適した確認 |
| --- | --- | --- |
| 日付変換の処理 | 入力に対して正しい日付を返す | 変換の回帰テスト |
| 画面の配置 | 実際の表示でボタンが所定の位置にある | 起動確認と画面の目視確認 |
| 配布設定 | 利用者向けの成果物が必要なファイルを含み起動する | 配布物を作成し、その成果物を起動する |
| 性能の変更 | 同じ条件で処理時間や処理量が改善している | 同じ入力・設定で変更前後を測る |

最初の例で画面テストや性能測定まで行う必要はありません。どの変更でも同じ検査を大量に実行するのではなく、依頼で約束した結果を直接確かめる方法から始めます。必要な確認を選べば、関係のない実行結果やログを調べる量も抑えられます。

## 確認方法を選ぶ

1. 依頼の完了条件を読み、「何が正しければ完了か」を言葉にします。
2. その性質を直接確認できるテスト、ビルド、実行、画面確認、測定などを選びます。
3. 結果が対象の変更に触れているか確かめます。
4. 影響が共通機能や配布物まで及ぶ場合、または結果だけでは判断できない場合に追加確認します。

たとえば構文検査が成功しても、日付が正しく変換されることは分かりません。画面の自動テストが通っても、Acceptanceに含まれる視覚的な配置を確認できるとは限りません。実行結果を、実際には確認していない性質の根拠として扱わないでください。

## 検査結果を確かめる

終了コードが成功でも、対象を検査していなければ完了の根拠になりません。実行したものが変更箇所を含み、必要な入力や条件を使ったかを確認します。

- テストが0件なら、対象機能を確認したことにはなりません。
- 検査対象の指定がずれていれば、成功表示でも対象の確認にはなりません。
- ビルド成功だけでは、配布物に必須ファイルが含まれるか分かりません。
- 画面確認が必要なら、テスト結果だけで見た目を推測しません。

ファイルを作る検証は、可能なら一時フォルダーで行います。作業ツリーに検証用データが混ざらず、作業前と同じ状態から再確認できます。生成した配布物そのものが完了条件の確認に必要なら、一時的に検査対象へ戻し、確認後はログや生成物の全文を通常の作業メモへ残しません。

## 実行条件に左右される場合

乱数、時刻、環境設定によって結果が変わる場合は、可能なら入力・設定・乱数の種・時間刻みなどを固定します。同じ条件で再実行しやすくなり、実行ごとの差を大量に読み比べずに済みます。

動作の原因を調べるときは、状態・イベント・判断結果など、今回の疑問に答える値を短い構造化ログに記録します。成功時は確認結果の要約だけを残し、失敗時は原因を判断する範囲だけ追加します。

## どこまで実行するか

変更した場所から関連テストを選ぶ方法は、[変更の影響から検証範囲を選ぶ](変更の影響から検証範囲を選ぶ.md)で説明しています。共通部品、公開形式、複数の利用側に影響する変更や、影響先を絞りきれない変更は、関連機能全体など広い確認へ進みます。必要な確認を実行できなかった場合は、未確認の範囲を報告します。

画面を起動せずに確かめられる処理や保存形式は、先に自動検査できます。ただし、見た目や操作が完了条件に含まれる変更では画面確認も行います。配布物がソースと異なる場合は、必要に応じて実際の配布物を起動します。

## 確認結果を記録する

完了報告には、確認した対象・結果・未確認範囲を短く残します。成功ログ全文は不要です。

```text
確認:
- 日付変換テスト: 12件成功
- CSV読み込みテスト: 8件成功
- 画面表示: 対象外
- 未確認: なし
```

## 使うとよい場合・不要な場合

変更のたびに検査一式を実行している、テスト結果だけでは完了条件を確かめられない、配布物や画面などソース以外の確認が必要、といった場合に役立ちます。変更と完了条件の組み合わせから確認方法を選べます。

小さな変更で対象テストが明確なら、そのテストとプロジェクトで定めた完了時の確認だけで足りることがあります。確認項目を形式的にすべて実施する必要はありません。一方、正しさを確かめるのに必要な検査は、時間やログを減らすためだけに省きません。

## AIへの依頼例

> 完了条件ごとに何を確かめるか選び、今回必要な検査だけを実行してください。各検査が確かめた範囲、コマンド、結果、失敗後に広げた確認、未実施項目を分けて報告してください。
