# コーディングエージェントの種類と選び方

**確認日：2026年10月16日。** Codex、Claude Code、Grok Build以外も含む製品の紹介です。ランキングではありません。機能・価格・提供状況は変わるため、導入時は各公式資料を確認してください。

## コーディングエージェントとは何か

AIモデルに、作業に必要なコード・仕様・テストなどを渡し、検索・編集・コマンド実行・検証といった道具を使って開発作業を進める仕組みです。**実行できる操作と、利用者の承認が必要になる操作は製品や設定で違います。**

| 区別するもの | 役割 | 例 |
| --- | --- | --- |
| AIモデル | 文章やコードを生成し、次の行動を判断する | GPT、Claude、Gemini、Grokの各モデル |
| コーディングエージェント | モデルへ情報を渡し、ファイル検索・編集・テストなどの道具を動かす | Codex、Claude Code、Grok Build、Gemini CLI |
| 作業環境 | コードをどこで扱い、コマンドをどこで実行するか | 開発者の端末、IDE、クラウドの仮想環境 |

例えば**GrokというAIモデルをCursorで使うことと、Grok Buildというエージェントを使うことは別**です。また、ターミナルで動くツールでも、モデルの推論には外部サービスへ情報を送る場合があります。コードの保存先、モデルの送信先、実行するコマンドの場所を区別してください。

## 主な製品

次の区分は**使い始める入口の目安**で、製品がその方法に限定されるわけではありません。名称・使い方は公式資料をもとに確認しています。

## 自分の作業に合うものを選ぶ

| 確認すること | 選ぶときの考え方 |
| --- | --- |
| 作業する画面 | 普段使うターミナル・エディターで操作するか、GitHubのIssueから任せるか。 |
| 調査と変更の範囲 | 一ファイルの修正か、複数ファイルの調査・変更・テストか。 |
| 操作の許可 | ファイル編集、シェルコマンド、ネットワーク接続、外部サービス変更の権限を確認できるか。 |
| モデルとデータの扱い | 選べるモデル、APIキー、送信先、ローカル推論の可否を確認する。 |
| 結果の確認 | 実際の変更差分、使った根拠、コマンドとテスト結果、未確認範囲を見られるか。 |
| 利用料金 | 月額、リクエスト、トークン課金などを公式の最新条件で調べる。 |

最初は**読み取りだけ**の小さな依頼で、エージェントが調べる範囲を確認します。

```text
設定ファイルを読み込むコードと関連するテストを探してください。
候補ファイルのパス、選んだ理由、まだ調べていない範囲を報告してください。
この段階ではファイルを編集せず、外部サービスへの変更も行わないでください。
```

報告を確認した後、対象の元コードと仕様・テストを確かめさせ、必要な修正と検証を依頼します。AIが「検証した」と述べただけで正しさを判断せず、差分と実際の結果を確認してください。

## ObaPickの手法と併用する

ObaPickは特定のコーディングエージェントを必須にしません。目的に合うコードや資料を選び、必要な根拠を残したまま、関係の薄い情報を渡さない方法を説明します。

- [コンテキスト削減の基本](../手法/AIに読む情報を絞る3つの方法.md) — 何を省き、何を残すか。
- [変更に必要なファイルから読む](../手法/今回読むファイルを選ぶ.md) — 作業に関係するコードとテストの探索。
- [AI利用でよくある質問](よくある質問.md) — モデルと編集方法の選び方。

`AGENTS.md`、`CLAUDE.md`、`GEMINI.md` などをいつ読むかは製品や設定によって違います。**ObaPickの文書を置くだけでAIが自動的に読むとは限りません。** 必要な資料の場所を明示して使ってください。

## この一覧の更新方針

公式の製品資料を優先し、終了状況や名称変更を確認します。測定条件がないまま「最強」「最も安い」と順位付けしません。新しい製品を追加するときは、使う場所、できる操作、権限、公式の参照先を示してください。
