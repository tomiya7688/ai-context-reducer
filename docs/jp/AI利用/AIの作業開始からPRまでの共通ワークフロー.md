# AIの作業開始からPRまでの共通ワークフロー

Claude Code、Codex、ChatGPT、GitHub Copilotのどれを使っても、**古い状態のリポジトリを前提に仕事を始めない**ための手順です。4つのAIの共通規則は [AGENTS.md](../../../AGENTS.md) を正本とします。この文書は作業の順番と、止まるべき条件を説明します。

**原則：ローカルのGitを操作できるAIは、作業内容の本格的な調査やファイル編集より先に、`main` の `git pull --ff-only origin main` を成功させます。** 作業ブランチは更新後の `main` から作ります。コマンドを使えない環境で「pull済み」と報告してはいけません。

## 1. 最初に安全を確認し、必ずpullする

AIがリポジトリを引き継いだら、最初の操作は**状況の確認と同期**です。調査、実装、Issueの解決案の確定、既存ファイルの編集を先に始めないでください。

新しい作業を始める場合の標準手順を示します。以下は `origin` が共有リモートで、通常の作業ブランチが `main` から分かれるリポジトリの例です。

~~~bash
# まだコードを編集しない。まず作業場所・未保存の変更・現在のブランチを調べる。
git rev-parse --show-toplevel
git status --short
git branch --show-current
git remote -v

# 未コミットの変更がなく、mainへ移動できることを確認した場合だけ続ける。
git switch main
git pull --ff-only origin main
git rev-parse HEAD

# pull成功後に初めて今回の作業ブランチを作る。
git switch -c docs/issue-number-short-description
~~~

最初の4コマンドは、既存作業を壊さずpullできるかの**事前確認**です。新しい仕事を始める前の必須同期を省いてよい、という意味ではありません。 `git status --short` に出る変更・未追跡ファイルがあれば、その所有者と扱いを確認し、勝手に作業ツリーをクリーンにしません。 `git switch main` に失敗した場合も強行しません。

`git pull --ff-only` は、リモートの変更を取得し、ローカルの履歴を**早送りだけ**で更新します。ローカルで別のコミットが進んでいて早送りできなければ失敗し、黙ってマージコミットを作りません。成功したことと、作業開始時点のコミットIDを記録します。

**pullが失敗したら作業を止めます。** ネットワーク障害、認証失敗、リモート名の違い、mainが存在しない、作業中の変更、早送りできない履歴など、原因と確認できた範囲を報告してください。ユーザーの許可なく `git stash`、`git reset --hard`、`git clean`、`git rebase`、強制push、競合を自動解消するマージはしません。再試行で他人の変更を消してはいけません。

## 2. 既存ブランチ・worktree・Gitを使えない環境

新規作業と、前回のブランチで続きを行う作業は区別します。

| 状況 | 作業開始前に行うこと | 禁止・注意点 |
| --- | --- | --- |
| **新しい作業／通常のローカルGit** | クリーンなmainへ移動して `git pull --ff-only origin main`。成功したmainから新しいブランチ | pull前に編集しない |
| **既存の作業ブランチで継続** | 作業ツリー・現在ブランチ・追跡先を確認。追跡先があり安全に早送りできるなら、そのブランチで `git pull --ff-only`。さらに `git fetch origin main` でmainの更新を確認 | mainが進んでいたら必要な統合方法を判断する。無断のrebase/mergeをしない |
| **Git worktreeでmainが別作業場所にある** | `git worktree list` で所有場所を調べる。mainを使っている作業場所の状態を確認して同期するか、最新のリモートmainから安全な別作業場所を用意 | 他のworktreeを強引に切り替えたり、未コミット変更を消さない |
| **一時的なCI環境／detached HEAD** | 環境が管理するcheckoutと対象のリモートコミットを確認。可能なら `git fetch` で最新のmainを確認 | pullで更新できないcheckoutを無理に書き換えない |
| **ChatGPTのGitHub接続など、シェルでGitを実行できない** | GitHubのリモートmainの最新SHA、対象ブランチ、作業の基点を再取得し、編集・PR作成前に差分を照合 | GitHub APIで最新SHAを取得したことを「git pullした」と言い換えない |

継続中のブランチでは、そのブランチに追跡先がなく `git pull` が使えないことがあります。その場合も、勝手に異なるブランチを統合するのではなく、最新のリモート状態を取得し、作業の基点と統合方法を確認してください。ユーザーが別のブランチを指定している場合は、意図した変更を失わないことを優先します。

GitHub Actionsの通常の検査ジョブは `actions/checkout` で指定されたコミットを検証するので、**CIで勝手にmainをpullして検査対象を変えません**。この文書の「作業開始時にpull」は、継続して開発するAIと作業場所の同期手順です。

## 3. 最新の状態を基にIssue・対象を決める

同期に成功した後、依頼されたIssue・PRと関連する変更履歴を確認し、既に完了した内容を重複実装しません。作業する目的、編集してよい範囲、完了条件、参照する原典を明らかにします。

最初からリポジトリ全体を読み込まず、ファイル名・見出し・検索結果から候補を選び、仕様、実装、テストの**必要な原文**を確認します。索引や要約だけを根拠に変更しません。[変更に必要なファイルから読む](../変更に必要なファイルから読む.md)を使ってください。

他のAIが同時に作業していれば担当ファイルと作業場所を分けます。[複数のAIに担当と編集範囲を分けて頼む](../手法/複数のAIに担当と編集範囲を分けて頼む.md)で統合担当と共有ファイルを決めます。

## 4. 必要な範囲だけ編集し、適切に確認する

作業中は差分を小さく保ち、作業目的と関係ない変更や新しい依存を勝手に追加しません。日本語の文書を変更したときは対応英訳と `docs/DOCUMENT_MAP.json`、目次やリンクも確認します。

文書を変更した場合、実行可能なら次の検査を行います。

~~~bash
python3 .github/scripts/test_validate_documentation.py
python3 .github/scripts/validate_documentation.py .
~~~

コードの変更なら対象のテストや静的検査を選んで実行します。テストの失敗、未実行、対象外を成功と表現しません。作業途中にmainへ変更が入ったときも、自分の変更を他人の作業へ無断で上書きしてはいけません。

## 5. PRの前に差分・最新main・競合を確認する

コミット・PRの前に、変更ファイルと差分を確認します。新規ブランチの例です。

~~~bash
git status --short
git diff --check
git diff --stat
git fetch origin main
git log --oneline --left-right HEAD...origin/main
~~~

`git diff` は未コミットの差分を対象とするため、コミット済みの変更は `git diff origin/main...HEAD` などでも確認してください。mainが進んでいても、pull済みという理由だけで最新と決めつけません。差分や競合を確認し、必要な統合方法を明示します。無断の履歴書換えや強制pushは行いません。

PRには対象Issue、目的、変更の理由、検証コマンドと結果、未確認事項を記します。GitHub Actionsの結果を確認し、PRが未マージなら未マージと報告します。ユーザーが求めた作業の完了と、mainへ取り込まれたことは別です。

## 6. 次のAI・チャットへ短く引き継ぐ

一つのチャットに無関係な作業を増やし続けません。担当が変わるときは、作業目的、開始コミット・現在のブランチ、変更したファイル、完了条件、確認結果、未解決の問題、PRリンクを引き継ぎます。長いログや会話全文をコピーせず、必要な場所を伝えます。

新しいAIが作業を再開するときは、**引継ぎの「最新だった」という説明を信じるだけでなく、改めて最初の同期・確認から始めます。** 詳しくは[作業ごとにAIの役割とチャットを分ける](作業ごとにAIの役割とチャットを分ける.md)を参照してください。

## 最初の操作を確認するための依頼例

~~~text
このリポジトリのAGENTS.mdと共通ワークフローに従ってください。
コード調査・編集を始める前に、Gitの状態を確認し、
安全な作業場所のmainで git pull --ff-only origin main を実行してください。
成功したコミットIDを報告してから対象Issueと必要な原典を確認してください。
未コミット変更・pull失敗・競合があれば勝手に片付けず停止し、原因を示してください。
Gitコマンドを実行できない環境なら、その事実を示して
リモートの最新コミットと作業基点を確認してください。pull済みとは報告しないでください。
~~~
