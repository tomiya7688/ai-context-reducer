# 作業用メモ（Context Pack）

Context Pack は、**いま進める作業の目的・対象・守る条件・完了の判断方法を、着手時に読める短いメモにしたもの**です。長い会話や Issue、リポジトリ全体を毎回読み直さずに済むよう、今回必要な情報と原典への参照をまとめます。

## 例：CSV の日付変換を直す

Issue に「CSV 読み込みで日付がずれる。直して」とだけ書かれていると、担当者は対象の読み込み処理、既存テスト、対応する日付形式、変更してよい範囲を探し回ることになります。今回の作業に必要なところを、たとえば次のように渡します。

```markdown
# 今回の作業
- 目的: CSV の YYYY-MM-DD を読み込んだとき、日付が前日にならないようにする
- 対象: `src/csv/date_parser.py` と対応するテスト
- 守る条件: 既存の CSV 形式と公開 API は変えない
- 完了条件: 問題を再現するテストが追加され、関連テストが通る
- 先に読む: この Issue の再現例、`src/csv/README.md`
- 今回はしない: CSV 全体の設計変更、タイムゾーン機能の追加
```

これで担当者は、目的に関係する処理とテストから読み始められます。会話や Issue 全体の再確認は、記載された参照先だけでは条件が決まらないときに行います。ファイル名や完了条件がまだ分からない場合は推測で埋めず、未確定であることを残して原典を確認します。

## 何を入れるか

作業ごとに必要な項目だけを残します。

| 項目 | 書くこと | 例 |
| --- | --- | --- |
| 目的 | 何をできる状態にするか | 読み込んだ日付が前日にならない |
| 対象 | 最初に調べるファイル、機能、テスト | 日付パーサーと対応テスト |
| 守る条件 | 変更してはいけない互換性や範囲 | 公開 API と既存 CSV 形式を保つ |
| 完了条件 | 終了を判断できる結果や確認 | 再現テストと関連テストが通る |
| 参照先 | 判断に使う原典への入口 | Issue の再現例、機能 README |
| 対象外 | 今回広げない作業 | タイムゾーン機能の追加 |

すべての作業で全項目が必要なわけではありません。小さな変更なら、目的・対象・完了条件だけで足ります。逆に、互換性や安全性など守る条件がある作業では、それを明記します。

## 原典との関係

Context Pack は今回の作業のための案内メモで、仕様や履歴の保管場所ではありません。判断の根拠は Issue、正式な設計文書、ソースコード、テストなどの原典に残し、Context Pack には必要な参照先と今回使う条件を記載します。同じ仕様を両方に書くと食い違うため、長期に有効な説明は原典へ置きます。

作業が終わったら一時メモを次の作業へ継ぎ足しません。継続が必要な決定や未完了項目は、Issue や正式な文書に記録します。Context Pack が長くなったら項目を増やす前に、今回の完了判断に不要な説明を外します。

## いつ使うか

複数の資料やファイルをまたぐ作業、会話をまたいで再開する作業、依頼文だけでは対象や完了条件が見えにくい作業で役立ちます。変更が一か所で、指示だけで対象と結果が明確なら、別のメモを作らずその指示を使えば十分です。

## テンプレート

必要な項目だけ残して使います。空欄を埋めるために情報を推測したり、全項目を機械的に追加したりしないでください。

- [Context Pack テンプレート](../../templates/CONTEXT_PACK.md)

## AIに渡す依頼例

作業メモをAIが自動で読むとは限りません。単発の作業では、ファイルを添付するかパスを依頼文に書きます。繰り返し使う場合は、利用するAIの実際の読込設定を確認してください。

> 添付した作業用メモの目的、守る条件、完了条件に従ってください。記載された参照先だけでは判断できない点があれば、推測で埋めず質問してください。最後に完了条件ごとの確認結果と未確認項目を示してください。

## 補助ツール・用語

必要なら[context-pack-builder](../../tools/common/medium/context-pack-builder/README.md)が依頼資料から、目的・参照先・完了条件をまとめた作業メモの草案を作ります。内容は原典と照らして確認してください。作業ごとに必要事項をまとめる方法は **Context Pack（作業用メモ）** と呼ばれます。
