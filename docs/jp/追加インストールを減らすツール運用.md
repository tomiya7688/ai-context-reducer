# 追加インストールを減らしてツールを使う

補助ツールを使うためだけに、利用者へ新しい言語環境や開発キットの導入を求めないようにします。手元にある環境や、配布済みですぐ使えるツールから選び、必要な確認に足りない場合にだけ別の方法を検討します。これにより、作業のたびに大きな実行環境を準備したり、その手順を調べたりせずに済みます。

インストールを減らすこと自体が、AIのコンテキストを直接減らすわけではありません。検索ツールが候補の場所だけを返し、AIに必要なコードだけを渡せる場合に、読む量も減ります。ツールの出力全体や導入手順を毎回AIに読ませるなら、コンテキストは減りません。

## 例：Pythonがない環境でコードを探す

AIがコード検索を手伝うために、利用者のWindows環境へPythonを入れる必要があるとします。検索だけが目的なら、配布済みの実行ファイルや、すでに使える検索コマンドで足りる場合があります。その方法を使えば、Pythonの導入や設定をせずに、関係するファイルを探せます。

一方、型やビルドの正しさを確かめる作業には、言語の実行環境や開発キットが必要な場合があります。開発キットとは、プログラムを組み立てて動作確認するための道具一式です。必要な環境がなければ、利用可能な別の確認に切り替えるか、その検査はできなかったと伝えます。結果を確認済みとして扱うために、環境を黙ってインストールしてはいけません。

## 選び方

まず目的に対してどの程度の確認が必要かを考え、手元で使える方法から選びます。単純な検索なら、検索コマンドや軽い内蔵機能でよい場合があります。プロジェクト全体の依存関係やビルドまで調べる必要があるなら、すでに利用できる言語別の道具を使います。小さな作業に大きな解析環境を持ち込む必要はありません。

外部ツールがすでに使えるなら利用して構いません。入っていない場合は、内蔵機能や簡易な方法で足りるかを確認します。どの方法でも確認できない要件は未確認として残し、追加環境が本当に必要な場合だけ導入手順を相談します。

このrepositoryでツールを選ぶ動作や、コマンド、ファイルの配置・上書き方法を確認する場合は、[`language-setup`](../../tools/common/small/language-setup/README.md)、[`materialize-tools`](../../tools/common/small/materialize-tools/README.md)、[`acr-toolbox`](../../tools/common/native/acr-toolbox/README.md)の説明を参照してください。
