# 変更に必要なファイルから読む

依頼を実装し、正しくできたか確かめるために必要なファイルから読みます。「変更に関係するファイル」とは、変更する処理、その処理の決まり、動作を確かめるテストです。外部へ渡す形式や呼び出し方も変える場合は、その形式を使う側も含めます。

## 例：CSVの日付表示を変える

CSVの日付を `2026/10/05` から `2026-10-05` に変える依頼なら、読む候補は次のとおりです。

1. CSVの日付文字列を作っている処理
2. 出力された日付の形式を確認しているテスト
3. CSVの形式を定めた説明や見本があれば、その該当部分
4. その形式を読み取る別のプログラムがあり、形式変更の影響を受けるなら、その読み取り処理

画面表示、ログイン処理、CSVの読み込みなど、今回の出力形式を実装・確認するのに使わないファイルは、最初から読む必要はありません。こうして候補を絞ると、無関係な資料を探す時間とAIに渡す量を減らせます。

## 大きなファイルは必要な箇所を探す

候補にしたファイルが大きくても、最初から全部読む必要はありません。日付を作る関数名や「CSV」「日付」などの語で場所を探し、その処理、呼び出し元、関連テストの周辺を読みます。ファイルが小さくても、仕様や直接のテストなら先に確認します。大きさや過去の変更回数だけでは、今回読むかどうかを決めません。

## 読む範囲を広げるとき

テストが失敗したら、失敗した処理や入力例を作る箇所を追加で読みます。CSVの形式を使う別のプログラムが見つかったら、その利用側も確認します。仕様と実装が食い違っている場合は、どちらが正しいかを決める資料を探します。新たな影響が見つかったときに、その原因を確かめる分だけ候補を広げます。

変更する場所と確認方法が明らかな小さな修正では、読む順を別に計画しなくても構いません。読む候補が多く、どれが実装や確認に必要か迷うときに使います。

## AIへの依頼例

単発なら、この文書を依頼に添付するかパスを示し、AIに次の順で進めるよう頼みます。

> 依頼された振る舞い、仕様、対応テストから読む候補を選び、パスと理由を先に示してください。形式やAPIの利用側に影響する場合は、その利用側も候補に加えてください。選んだ原典を確認し、読んだファイルと検証結果を報告してください。

## 補助ツール・用語

必要なら[context-budget](../../tools/common/large/context-budget/README.md)で候補の概算サイズを、[hotspot-report](../../tools/common/large/hotspot-report/README.md)で大きい・深いファイルを調べられます。どちらも調査候補を選ぶ補助情報であり、大きさは関連性の判断には使いません。この方法は **Context Priority** と呼ばれます。
