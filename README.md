# ai-context-reducer

日本語 | [English](README.en.md)

AIに作業を頼む人に向けて、必要なコードや資料を選んで渡す方法を紹介するプロジェクトです。次の3つを公開しています。

- **手法の説明** — 何を読ませ、どこまで調べさせるかを決める方法と、AIへの依頼例。
- **導入用のひな型** — 作業ルール、プロジェクトの情報、今回の作業メモを書ける文書のひな型。
- **補助ツール** — ファイル検索、作業メモの作成、ルールの確認、実行するテストの選定を助けるプログラム。

依頼例やひな型を、普段使うAIに渡すだけでも始められます。調査や確認、文書作成を省力化したいときは、補助ツールも使えます。AIが作業のために受け取る指示やコード、資料、検索・確認の結果などを「コンテキスト」と呼びます。

## 例：保存した設定が再起動後に消える不具合を直す

架空のアプリを使った説明用の例です。画面で保存した設定が、アプリを再起動すると元に戻るとします。

```text
広く読ませる場合
  プロジェクト全体を渡して、AIに原因を調べさせる
  → 設定に関係のない画面や機能のコードまで読ませる

読む範囲を絞る場合
  AIに設定の保存・起動時の読み込み処理と、対応するテストを検索させる
  → 関係するコード・設定の仕様・テストを読ませる
  → 他の処理も関係すると分かったら、その部分も確認させる
```

どちらも、保存した設定が再起動後に保たれるように修正する作業です。修正後は、同じ設定を保存して再起動し、設定が保たれるか確かめます。

読む範囲を絞ると、設定に関係のない画面や機能のコードを渡す量を抑えられます。設定の仕様や関連テストは読ませ、動作確認も行うことで、必要な情報を保ちながら修正を進めます。

## 初めて読む方へ

目的に合わせて、次の順で読んでください。すべての文書を読む必要はありません。

1. **方法を知りたい**: [コンテキスト削減の基本](docs/jp/コンテキスト削減の基本.md)で全体像をつかみ、[手法一覧](docs/jp/手法一覧.md)から今の困りごとに合う説明を一つ選びます。初めて実際のコード変更に使うなら、まず[変更に必要なファイルから読む](docs/jp/変更に必要なファイルから読む.md)を読んでください。
2. **自分のプロジェクトに取り入れたい**: [導入優先度](docs/jp/導入優先度.md)で繰り返し起きている困りごとに合う方法を選び、[導入依頼文](docs/jp/AIに読み方の仕組みを整えてもらう.md)で既存の案内や手順を確認します。継続利用する案内は[AI_CONTEXT.mdのひな形](templates/AI_CONTEXT.md)で短く整理し、利用中のAIが実際に読む指示ファイルへ置きます（対応していれば`AGENTS.md`など）。
3. **補助ツールを使いたい**: 先に目的に合う手法を選び、必要な場合だけ[手法と補助ツールの対応表](docs/jp/手法と補助ツールの対応表.md)からツールの説明へ進みます。ツールの追加は必須ではありません。

手法の文書は、依頼に添付するかパスをAIへ伝えて使います。自動で読まれるとは限らないため、繰り返し使う場合は利用中のAIが読む指示や設定に登録してください。


## 情報を絞る三つの方法

### 1. 機械で分かることは、先に機械で調べる

ファイル名、関数名、読み込んでいる別ファイルなどを検索や解析で調べ、変更に関係しそうな候補を絞ります。AIに大量のコードを読ませて一覧を作らせる手間を減らし、判断に必要な実装へ早く進めます。設計上の意味は、候補を絞った後に元のコードを読んで確認します。

### 2. 繰り返す手順をまとめる

毎回同じ順番で変更箇所とテストを探すなら、短い案内や補助ツールに手順をまとめます。作業のたびに探し方を考え直す必要がなくなります。一度きりの作業や、仕組みを保つ手間の方が大きい場合は作りません。

### 3. 関係する部分だけ読む

変更場所を見つけたら、その実装、説明、テストのうち今回必要な部分を読みます。全部を読まずに済みますが、必要な根拠まで省かないよう、判断や確認では元の資料に戻ります。

三つの方法の詳しい説明は[コンテキスト削減の基本](docs/jp/コンテキスト削減の基本.md)にあります。

## このリポジトリにあるもの

中心は、作業の案内や情報の絞り方を説明する文書とテンプレートです。検索・一覧作成・確認手順の一部を補助するツールもありますが、どのツールもすべてのプロジェクトに必要というわけではありません。

- 作業の困りごとから手法を探す: [手法一覧](docs/jp/手法一覧.md)

## 既存プロジェクトで試す

まず[導入優先度](docs/jp/導入優先度.md)で繰り返し起きている困りごとを一つ選び、[導入依頼文](docs/jp/AIに読み方の仕組みを整えてもらう.md)を使って既存の案内や作業手順を確認します。導入後、必要なコードとテストへ進みやすくなったか、確認不足が生じていないかを確かめます。

## 手法をAIに使わせる

一度だけ使う場合は、選んだ手法の説明を依頼に添付するか、文書のパスを書き、そこにある例を今回の作業に合わせて頼みます。繰り返す場合は、説明へのリンクと適用条件を、利用中のAIが実際に読むプロジェクト指示へ置きます。どのファイルを自動で読むかはAIツールごとに異なるため、設定を確認します。

たとえば、変更するファイルとテストを絞るなら、次のように依頼します。

```text
変更の目的は設定読込時のエラー理由を表示することです。
設定読込処理と対応テストの候補を、パスと選んだ理由付きで先に示してください。
選んだ元コードとテストを確認し、必要な変更とテストを行ってください。
最後に、読んだファイル、実行した確認と結果、未確認の範囲を報告してください。
```

効果は、無関係なファイルをAIへ渡さず、その分の入力を減らせることです。利用者は報告されたファイル・コマンド・結果を差分や表示できる作業記録と照らします。読み込み記録やトークン計測がない環境では、実際の使用量が減ったとは断定せず、必要なコードとテストを保ったまま調査先を絞れたかを確認します。
