# ai-context-reducer

日本語 | [English](README.en.md)

AIに作業を頼む人に向けて、必要なコードや資料を選んで渡す方法を紹介するプロジェクトです。次の3つを公開しています。

- **手法の説明** — 何を読ませ、どこまで調べさせるかを決める方法と、AIへの依頼例。
- **導入用のひな型** — 作業ルール、プロジェクトの情報、今回の作業メモを書ける文書のひな型。
- **補助ツール** — ファイル検索、作業メモの作成、ルールの確認、実行するテストの選定を助けるプログラム。

依頼例やひな型を、普段使うAIに渡すだけでも始められます。調査や確認、文書作成を省力化したいときは、補助ツールも使えます。AIが作業のために受け取る指示やコード、資料、検索・確認の結果などを「コンテキスト」と呼びます。

[最新の配布物](https://github.com/tomiya7688/ai-context-reducer/releases/latest) · [約5分で補助ツールを試す](docs/jp/導入/AIに渡す資料を選ぶ道具を試す.md) · [手法一覧](docs/jp/手法/困りごとから手法を探す.md)

配布中の v1.0.0 は Windows・Linux・macOS の x64 / arm64 に対応しています。概要と操作案の表示には、言語環境の追加インストールは不要です。

## 例：保存した設定が再起動後に消える不具合を直す

架空のアプリを使った説明用の例です。画面で保存した設定が、アプリを再起動すると元に戻るとします。

```text
広く読ませる場合
  プロジェクト全体を渡して、AIに原因を調べさせる
  → 設定に関係のない画面や機能のコードまで読ませる

読む範囲を絞る場合
  AIに設定の保存・起動時の読み込み処理と、対応するテストを検索させる
  → 関係するコード・設定の仕様・テストを読ませる
  → 他の処理も関係すると分かったら、その部分も確認させる
```

どちらも、保存した設定が再起動後に保たれるように修正する作業です。修正後は、同じ設定を保存して再起動し、設定が保たれるか確かめます。

読む範囲を絞ると、設定に関係のない画面や機能のコードを渡す量を抑えられます。設定の仕様や関連テストは読ませ、動作確認も行うことで、必要な情報を保ちながら修正を進めます。

## まず行うこと

- 作業の目的、守る条件、終わりの目安をAIへ伝える。
- ファイルを開く前に名前や内容を検索し、関係するものから読む。
- 詳しい説明を一か所に置き、他の場所には読むタイミングとリンクを書く。
- 必要な資料が見つからないときや、共有部分を変更するときは調査範囲を広げる。
- 変更に合うテストや動作確認を行い、確認していないことも伝える。

関係する資料とテストを選んでAIに渡すと、無関係なファイルや長いログを読む前に作業を始められます。必要な情報まで省くと誤った変更につながるため、正しさを確かめる資料とテストは残してください。

## 困りごとから説明を探す

AIに作業を頼むときに人が感じる困りごとから、次に読む説明を探す表です。

| 困りごと | 説明 |
| --- | --- |
| 作業を頼むたび、AIに何を渡せばよいか迷う | [作業の種類ごとに、AIに最初に読む場所を伝える](docs/jp/手法/作業の種類ごとに、AIに最初に読む場所を伝える.md)、[変更内容ごとに読む場所と確認方法を一覧にする](docs/jp/手法/変更内容ごとに読む場所と確認方法を一覧にする.md) |
| AIへの依頼で、変更内容や完了の判断基準を決められない | [作業を始める前に、目的と終わりを決める](docs/jp/手法/作業を始める前に、目的と終わりを決める.md) |
| 大きなコードから、依頼に関係する場所を見つけられない | [今回読むファイルを選ぶ](docs/jp/手法/今回読むファイルを選ぶ.md)、[関数や使われている場所を探す](docs/jp/手法/関数や使われている場所を探す.md) |
| コードの確認で、どの調べ方を使えばよいか迷う | [コードを解析するときは、言語に合った方法を選ぶ](docs/jp/手法/コードを解析するときは、言語に合った方法を選ぶ.md) |
| AIの調査が長引き、どこで切り上げるか判断できない | [AIに調査を止めさせる条件を決める](docs/jp/手法/AIに調査を止めさせる条件を決める.md)、[調査前に、原因を判断する確認項目を決める](docs/jp/手法/調査前に、原因を判断する確認項目を決める.md) |
| テストの場所を毎回探し直し、どの確認を頼めばよいか迷う | [変更に合った方法で動作を確かめる](docs/jp/手法/変更に合った方法で動作を確かめる.md)、[変更の影響から実行するテストを決める](docs/jp/手法/変更の影響から実行するテストを決める.md) |
| AIへの依頼に、長い規則や重複した説明を毎回含めている | [AIに作業場所に合った指示書を読ませる](docs/jp/手法/AIに作業場所に合った指示書を読ませる.md)（変更するファイルまでの指示書を順に読む）、[今回の作業に関係する決まりだけ確認する](docs/jp/手法/今回の作業に関係する決まりだけ確認する.md)、[同じ説明を何度も書かない](docs/jp/手法/同じ説明を何度も書かない.md) |
| AIに作業ルールやプロジェクト情報を何度も説明している | [AIへの作業ルール・プロジェクト情報・作業メモのひな型](templates/README.md) |

すべての仕組みを追加する必要はありません。繰り返し起きている問題があり、対策の手入れにかかる時間より、減らせる検索や確認の時間が大きいときにだけ加えます。

## ダウンロードと補助ツール

[GitHub Releases](https://github.com/tomiya7688/ai-context-reducer/releases) から、Windows・Linux・macOS向けの配布ファイルを取得できます。各OSでは一般的なCPU向けとARM CPU向けを配布します。配布ファイルには、ファイルやコード内の語句を検索したり、コードとテストの関係を調べたりする補助プログラムが含まれます。関連箇所だけを探してAIに渡せるため、無関係なコードや長い検索結果を読み込ませずに済みます。

複数の補助ツールをまとめた `acr-toolbox` も配布しています。コマンド入力欄から実行すると、版の表示、コードの調査、次に行う調査や確認方法の選定などに使えます。各ツールでできることと使い方は[補助ツール一覧](tools/README.md)で確認できます。すでに使っている検索やテストの方法があれば、そのまま利用できます。

配布ファイルの作成や公開方法など、このプロジェクトの管理者向け説明は [docs/internal/](docs/internal/README.md) にあります。利用者は読む必要がありません。
